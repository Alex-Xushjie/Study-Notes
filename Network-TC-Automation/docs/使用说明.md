# Network T&C Automation 使用说明

## 启动
双击项目中的 start.bat。更新程序后，请先关闭旧窗口再重新启动。

## 项目和设备
新建或打开项目 JSON。在设备页填写唯一Hostname、有效管理 IP、平台、端口、用户名；保存项目。设备 IP 必填，不接受主机名。Hostname也作为无法读取 SSH 提示符时的显示名称；请填写可识别的设备名称。

在设备页为每台设备填写 SSH 用户名和密码，再点击新增或更新设备。项目中的密码按当前 Windows 用户加密保存，运行后仅清除输入框。首次连接需核对设备指纹并写入当前用户 ~/.ssh/known_hosts。旧 Cisco IOL 镜像使用 requirements-legacy.txt 中的兼容依赖。

## 三种任务来源
- Excel：下载模板，填写 Devices 和 Test Cases，导入合并。Hostname须唯一；任务支持 Command 或 Library ID，Command 优先。Expected 为区分大小写的包含文本判断。
- 内置测试库：选择目标设备与测试项，加入队列。
- Quick Command：选择目标设备，填写单行查询命令及可选预期文本，加入队列。

队列支持编辑、删除、排序。执行整个队列前会要求确认命令。所有执行均使用真实 SSH，已移除模拟功能。停止后续任务不会强制中断当前网络调用，需要等待完成或超时。

## 结果与设备身份
SSH 采集先读取设备真实提示符，再执行命令，保留命令回显和末尾提示符，例如：

```text
CE-1#show ip interface brief
Interface ...
Ethernet0/2  192.168.153.111 ... up up
CE-1#
```

设备名从本次 SSH 会话提示符提取，例如 CE-1# 得到 CE-1。图片页眉只显示「设备名称 | IP 地址 | 执行的命令/操作」，每一页均保留设备身份。TXT 保存本次采集文本；PNG 是该文本的排版渲染图，并非 SSH 客户端窗口截图。提示符与连接 IP 用于追溯设备来源，不构成防篡改签名或设备资产认证。

PASS 表示包含预期文本，FAIL 表示未包含，REVIEW 表示没有预期文本，ERROR 表示连接或命令异常。人工复核保存独立 review.json，保留原始结果。

## 文件命名

```text
evidence/
  20261102-000838/
    CE-1-192.168.153.111-show_version-TC-001-01/
      CE-1-192.168.153.111-show_version.txt
      CE-1-192.168.153.111-show_version-001.png
      result.json
```

运行目录使用本机日期时间；重名增加序号。任务目录使用设备名-IP-命令-Test ID-序号；TXT 和分页 PNG 同样带设备名-IP-命令。空格转下划线，Windows 非法字符替换为下划线，过长字段会截短，完整命令保存在 result.json。目录序号防止重复执行覆盖。图片第二页起也显示相同设备信息。

结果页查看历史输出和设备 IP，打开任务目录查看图片。证据页可导出 ZIP。旧证据保留原位置，不自动改名；旧模拟记录不在结果列表和 ZIP 中展示。历史真实记录仍可查看，但没有采集过的提示符不会事后补造，请重新运行生成新格式证据。

## EVE-NG 联调
VMware 中将设备接口接入 Cloud0，配置可从 Windows 访问的管理 IP 并开启 SSH。工具连接设备 IP，不是 EVE 服务器 IP。

```powershell
Test-NetConnection 192.168.153.111 -Port 22
ssh lab@192.168.153.111
```

当前已在 Cisco IOL 15.7(3)M2（CE-1，192.168.153.111）验证版本查询、接口摘要、真实提示符采集与证据保存。其他平台需单独验证。暂不支持并发、定时任务、自动 enable 提权、Word 报告。

Excel 新模板使用 Hostname 列；旧模板 Device ID 列仍可导入。Hostname 请填写设备实际主机名，例如 CE-1。项目内部关联字段保持兼容；实际采集的 SSH 主机名仍来自设备提示符。


## 第一轮完善功能

### 测试项与多步骤
执行页选中一行，点击「编辑选中任务」，依次填写 Test ID、章节、测试名称、逻辑设备组、验收标准、自动判断文本和命令步骤（一行一条）。命令步骤属于同一个测试项，运行后生成一个汇总结果与一组证据；JSON 中保留各步骤的输出和错误。一个步骤失败仍继续采集其余步骤，测试项执行状态为 ERROR。取消操作在测试项之间生效。

「验收标准 / 项目预期」用于填写批准设计中的要求，供人工核对；「自动判断：包含文本」才参与简单的自动判断，两者不能混淆。当前未实现 OSPF 邻居逐项匹配等结构化判断。每个命令步骤独立建立 SSH 会话，不支持交互式配置步骤。

### 批量套用模板
先维护设备，在执行页点击「批量套用 T&C 模板」，勾选多台设备和多个测试项。首批模板仅支持 cisco_ios 与 huawei_vrp，包括身份、管理地址、NTP、VLAN、LACP、STP、OSPF 和路由表。命令是查询模板，需按实际型号、软件、权限检查和编辑；Huawei 及 Cisco 的全部模板尚未逐项实机验证，EVE IOL 的版本与接口摘要已验证。不自动执行保存配置、端口关闭或故障注入。

模板编号是工具编号，不是原 Word 自动编号；在编辑中填写你项目的正式章节与 Test ID。逻辑设备组可以填写 Stack-A 等；首版只是归组字段，不自动发现堆叠成员，也不会将物理成员视为同一个 SSH 连接。

### 勾选执行与复测
勾选队列第一列，再点击「执行勾选测试项」。全选和全不选可快速调整；新增、编辑和保存导致列表刷新后默认重新全选，执行前应检查。结果页支持多选记录后点击「复测选中记录」，生成新批次，保留旧证据，并在元数据与索引中记录 Retest Of。复测按选中历史记录的命令快照执行，连接地址使用当前设备清单。

### 人工结论与实际结果
结果页分别显示执行状态、自动判断和人工复核。执行完成不等于验收通过。复核支持 PASS、FAIL、REVIEW、N/A、PASS WITH COMMENTS，可以填写实际结果和备注。N/A 与带意见通过必须说明原因。复核当前可用于覆盖单个测试项结论，重复复核会更新 review.json；不提供多人审批或复核历史版本。

### 证据索引
证据页点击「导出结果与证据索引 CSV」，可用 Excel 打开。包含批次、设备、IP、章节、测试编号与名称、逻辑组、执行状态、自动判断、人工结论、实际结果、备注、验收标准、复测来源、命令以及 TXT/PNG/JSON 的绝对位置。索引路径供本机查找，拷贝到其他电脑后路径需重新定位。ZIP 保留证据目录结构。

多步骤测试项使用「设备名-IP-测试名称」作为文件名，避免将多个命令拼成超长名称；单条旧任务仍使用命令。PNG 顶部继续仅显示设备名称、IP 和操作名称，CLI 中保留每个命令的真实提示符及回显。

### Excel 与旧项目
新模板增加 Test Name、Section、Steps、Criteria、Logical Group。Steps 单元格内每行一条命令；填写 Steps 时运行这些步骤，Command 保留为代表命令且仍为必填（或由 Library ID 解析）。旧 Excel 和 schema_version=1 项目仍可打开；保存后使用 schema_version=2。默认不会改写已有项目，保存前可自行备份。

本轮未包含人工照片附件、缺陷工单、Word 自动回填、多设备联合状态判断或复杂规则引擎。

## 界面语言
窗口顶部「语言 / Language」可即时切换简体中文和 English，选择会在本机记忆。中文界面显示「主机名」，英文界面显示 Hostname。切换不清空设备输入、密码或任务勾选；命令、真实 CLI、用户填写的项目和测试内容保持原文，Excel 列名和 CSV 字段继续使用稳定的英文格式。


## 逐设备 SSH 账号密码

设备页支持两种录入方式：

1. 手动填写主机名、IP、平台、端口、SSH 用户名、SSH 密码和分组，再点击新增设备。编辑已有设备时，先载入选中设备，修改后点击更新选中设备。
2. 点击「从 Excel 导入设备和凭据」。新模板 Devices 表增加 Password 列，支持每台设备使用不同账号密码。可以只保留 Devices 工作表；有 Test Cases 时一并导入计划。

设置页仅保留通用超时等参数，不再填写统一账号密码。执行时逐台使用已保存的设备凭据，缺失时会提示补齐。密码输入显示为掩码，不在列表或执行日志展示。

项目 JSON 中使用 Windows DPAPI 保存加密凭据，不保存明文密码；同一 Windows 用户重开项目可以解密。拷贝到其他电脑或其他用户后需要重新填写密码。此版本的密码持久化依赖 Windows，macOS 适配尚未实现。

Excel 的 Password 列本身是明文，请妥善保管或在导入后清除。旧项目没有密码时，载入设备后补填并更新、保存。不要把项目加密理解为 Excel 文件也已加密。


## 自定义冗余测试工作流

入口：执行页 →「冗余测试工作流（可自定义）」。先保存项目，设备页填好逐设备凭据。工作流是独立的多阶段测试，不直接加入普通命令队列。

### 模板与编辑
预置九类起始模板：堆叠链路、M-LAG Peer-Link、上联、下联、聚合成员、主控板、电源、整台设备、VRRP 接口故障。它们提供通用阶段，默认故障操作由工程师完成，不代表已提供完整厂商验收命令。

单设备时，采集步骤预填版本与接口摘要作为起点；实际使用必须按测试目的替换或补充，例如堆叠状态、VRRP 角色、LACP 成员、硬件告警。多设备时逐步填写目标主机名。不要把版本和接口摘要当作完成所有冗余检查的充分证据。

支持新增、编辑、复制、删除、上移、下移；双击步骤也能编辑。目标主机名使用项目里的主机名，多个目标用逗号分隔；查询命令每行一条。可修改操作说明、等待秒数和可选的预期包含文本。模板保存为独立 JSON，可重新打开，或复制另存用于其他项目；不包含设备密码。

步骤类型：状态采集、人工确认、人工故障操作、CLI 故障操作、等待、人工恢复、CLI 恢复、最终复核。每个故障步骤之后必须安排恢复步骤，最后必须为最终复核。填好具体接口、部件、恢复方法及负责人后再开始。

### 执行
点击「开始新执行」，核对操作对象、变更窗口与管理路径。然后逐步点击「执行 / 确认完成本步」。采集在后台执行；等待步骤按设置时间结束；人工步骤必须明确确认已完成，并可在下方填写现场记录。人工确认时间不等于精确断链时间。

人工故障步骤显示时即保守记录为“可能已实施故障、待恢复”；即使还没实际操作，中止也会提示核对恢复。采集失败不自动进入下一步，可重试，或中止转入恢复。中止发生在命令完成或超时后，不会强制杀掉正在执行的 SSH 命令。

实施故障后点击中止，会跳到后续恢复步骤并继续恢复检查。无法恢复时必须填写原因与交接信息，点击「无法恢复，记录未恢复」，留下明确未恢复/失败记录。存在失败步骤或中止记录时，不允许直接选择无意见 PASS；可保留待复核或记录带意见结论。

### CLI 操作
普通状态采集仍是查询命令。只有显式选择 CLI 故障 / CLI 恢复步骤才会调用配置接口，执行前单独确认目标及完整命令。例如 Cisco 接口操作在步骤中配置：

```text
interface Ethernet0/1
shutdown
```

恢复步骤：

```text
interface Ethernet0/1
no shutdown
```

具体接口必须由工程师确认，不可使用未替换的占位符。当前配置接口不自动提权、不自动保存配置，也不保证管理失联后能自动恢复；需使用独立管理路径并准备现场恢复。CLI 配置发送机制已用模拟接口测试，尚未实际执行端口关闭/恢复验收。所有物理故障测试也尚需现场验证。

### 记录和异常继续
项目同级 workflow-runs/日期时间/workflow.json 保存步骤快照、设备 IP、事件时间、现场记录、阶段证据路径与结论；不包含密码。阶段 TXT/PNG/JSON 仍进入项目 evidence 目录，结果页可查看各阶段采集。最终工作流结论在 workflow.json 中，不会自动覆盖所有阶段结果。

窗口内可点击「继续执行记录」选择 workflow.json。若上次存在待恢复标记，会先进入恢复路径，不会重新注入故障；地址与原记录不一致时需先核对设备清单。程序异常退出后不会自动恢复设备，工程师应通过记录继续或现场恢复。

证据 ZIP 包含 workflow-runs 执行记录。CSV 索引列出阶段采集结果，工作流整体结论查 workflow.json。首版不含照片附件、持续业务打流、自动周期轮询、远程测试端、拖拽流程图或后台无人值守恢复。
