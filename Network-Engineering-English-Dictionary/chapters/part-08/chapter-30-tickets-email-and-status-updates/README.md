## Say it at work

> The issue affects one branch; we are investigating the return path.

> We have confirmed that the physical link is up.

> We suspect a routing issue, but the cause is not yet confirmed.

> The next update will be at 14:00 UTC.

## Quick review

1. Should a suspected cause be presented as confirmed?
2. What should accompany a test result?
3. When should you say an attachment is included?
4. What makes an update time unambiguous?

**Answers**

1. No; state the uncertainty.
2. The relevant source, destination, method, time, and limitations.
3. Only when it is actually attached.
4. A date when needed and a clear time zone or UTC offset.
