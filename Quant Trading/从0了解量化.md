1. 行情通道 (Market Data Channel) —— “看”

流量方向：单向（入方向为主）。从交易所广播给所有量化机构。

传输协议：UDP Multicast（组播）。因为交易所不可能给成百上千家机构各自发一份 TCP 单播（那样交易所服务器和带宽会瞬间崩溃），所以采用组播一次性推送到网络中。

数据内容：
- Tick Data / L1 / L2 / L3 盘口：买一卖一价、订单簿（Order Book）深度、逐笔成交（Trades）等。

网络优化重点：
- 零丢包 (Zero Drop)：UDP 是不可靠传输，在网络拥塞时最容易被扔掉。一旦丢包，策略看到的盘口就不完整，可能导致错误的交易决策。
- A/B 双路冗余 (Feed A/B Side-by-Side)：交易所通常会同时推两路完全一样的组播数据（A 路和 B 路走不同物理链路）。量化服务器通过 FPGA 或网卡做 Line Arbitration（链路仲裁）：哪一路先到就用哪一路，如果 A 路丢包，立刻用 B 路补上。
- 防微爆发 (Microburst)：开盘瞬间或剧烈波动时，组播流量会发生微秒级的峰值突发，极其考验交换机 Buffer。

2. 报单/交易通道 (Order Execution Channel) —— “算与发”

流量方向：双向（Out: 下单/撤单，In: 确认/成交回报）。

传输协议：TCP 单播（Point-to-Point）。交易涉及资金与持仓，要求100% 可靠传输与顺序保证。

数据内容：

- 上行 (Outbound)：New Order（报单）、Cancel Order（撤单）。

- 下行 (Inbound)：Execution Report（成交回报）、Order Ack/Reject（确认/拒绝）。

常见上层协议：FIX 协议（如 FIX 4.2/4.4，文本/二进制定制版）或交易所自研的 Native Binary 协议（如 HKEX OCG-C、CME iLink3）。

网络优化重点：

- 极致单向/往返延迟 (RTT Latency)：这里是真正的“拼速度战场”。

- Kernel Bypass（内核旁路）：TCP 传统协议栈需要经过操作系统内核，拷贝数据有微秒级开销。量化公司会在服务器上使用 Solarflare 网卡 + OpenOnload / EF_VI，将 TCP 协议栈直接移到用户态或 FPGA 硬件中，把建连和发送延迟压到纳秒/亚微秒级。

- 关闭 Nagle 算法 (TCP_NODELAY)：确保极小的数据包（如几十个 Byte 的报单指令）能立刻发出，不需要等待小包凑够 MSS。
