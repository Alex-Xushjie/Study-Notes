# 数据中心详细教材：把 EVPN 控制面连接到实际转发

[首页](../README.md) · [概念导读](01-EVPN-VXLAN.md) · [实验](02-Labs.md)

## 1. 先区分三个问题

Underlay 解决 VTEP IP 之间怎样可达；VXLAN 数据面解决原始帧怎样封装、跨越三层网络；EVPN 控制面解决远端 MAC/IP、前缀和多归属信息怎样分发。三个问题有关联，但不能用一个“BGP up”替代所有验证。

教学拓扑为两 leaf、一 spine，各 leaf 接一台服务器。Leaf-1 VTEP 10.255.0.1/32，Leaf-2 为 10.255.0.2/32；租户 Blue 的 VLAN10 对应 L2VNI10010，子网 10.1.10.0/24；后续增加 VLAN20/L2VNI10020 和租户 L3VNI50000。所有数字是教学选择。

## 2. Underlay：稳定传送外层包

先让 loopback/VTEP 地址双向可达，再启用 overlay。可采用路由交换基础熟悉的 IGP，也可用 eBGP；协议选择受团队、规模与运维约束影响，不是某个名称天然先进。

Underlay 应核对接口状态、链路地址、邻居、loopback 路由、ECMP 下一跳和 MTU。只 ping 相邻接口无法证明远端 VTEP loopback 可达。测试时用实际 VTEP 源地址，避免源地址改变而掩盖回程问题。

Spine 在基础两层 fabric 中传送外层 IP，不必知道所有租户 MAC。若承担 EVPN route reflector，这是额外的控制面角色，不代表业务数据经过 RR 处理。

## 3. VXLAN 封装到底增加了什么

同租户同子网的内层以太帧，在入口 VTEP 外包 UDP/IP/Ethernet。外层目的 IP 是远端 VTEP，VXLAN 头中的 VNI 用于标识逻辑网络。中间 spine 根据外层 IP 转发，通常不依赖内层租户地址。

无外层 VLAN、IPv4 且无 IP options 的常见模型中，外层 Ethernet14+IP20+UDP8+VXLAN8=50 字节。这里是封装开销的简化口径，不含所有线上开销。若内层 IP 包1500，加内层 Ethernet14 后，外层 IP 长度约1550。设备 MTU 的计数口径要核实，不能把1550机械写进所有平台。

ECMP 多依赖外层 hash，VXLAN UDP 源端口可为分流提供熵。多流总体均衡不意味着单流能同时使用所有路径。大流集中到同一出口仍可能拥塞。

## 4. RD、RT、VNI 和 VRF 分别回答什么

RD 使不同来源/实例的相同地址成为控制面可区分的路由；RT 决定导入/导出关系；VNI 参与数据面隔离和封装；VRF 保存租户三层路由上下文。它们不能互相代替。

| 对象 | Blue 示例 | 排错问题 |
|---|---|---|
| L2VNI | 10010 / 10020 | 帧属于哪个二层网络？ |
| L3VNI | 50000 | 跨子网路由属于哪个租户？ |
| RT | 教学约定 65000:10010 等 | 远端路由会被哪个实例导入？ |
| RD | 每 VTEP/实例唯一规划 | 相同 NLRI 如何在控制面区分？ |
| VRF | Blue | 地址在哪张租户路由表解释？ |

自动派生规则和厂商配置不一定相同。先做两端台账，再查实际导入结果。看到全局 EVPN 路由存在，只说明控制面收到，不代表租户实例已经导入。

## 5. Type 2/3/5：按用途理解

Type2 携带 MAC，且可包含 IP 绑定，帮助远端学习终端信息。Type3 用于建立 BUM 复制相关成员信息；具体数据复制可能用 ingress replication 或 underlay multicast。Type5 表达 IP 前缀，适用于租户前缀传播，但主机路由可能通过 Type2 携 IP 参与，不能把所有三层流量都说成必须 Type5。

多归属扩展再学习 Type1/4、ESI 与 DF。先分清单归属转发，避免一开始把所有路由类型混成命令表。

## 6. 同子网转发，逐步推导

主机 A 10.1.10.11 在 Leaf-1，B 10.1.10.22 在 Leaf-2。A 先解析 B 的 MAC。若已有有效 MAC/IP 绑定且平台开启 ARP suppression，入口可能代理回答；否则广播按该 VNI 的 BUM 机制送到相关 VTEP。

A 发往 B 的内层帧到 Leaf-1，查 Blue 对应 bridge/FDB 得到 B 在远端 VTEP；以 VNI10010 封装到10.255.0.2。Leaf-2 解封装后只在匹配的二层实例转发到 B。

应观测四处：入口服务器侧的内层帧、VTEP 外层包、远端解封装和远端服务器接收。缺一处时结合 FDB、EVPN 路由、VNI 状态和接口计数缩小范围。仅抓到 UDP VXLAN 包还不能证明 VNI 与终端出口正确。

## 7. 跨子网：对称 IRB 的思考方法

A 在 VLAN10，C 在远端 VLAN20。A 把包发给默认网关，入口 leaf 在 Blue VRF 查目的，按对称 IRB 模型通过租户 L3VNI 送到出口 leaf，再由出口查租户路由转到 VLAN20。

Anycast gateway 让各 leaf 在相应网段提供一致的网关地址/身份，实现本地接入路由；它不是随意复制所有接口地址。必须一致规划网关与租户绑定，检查重复地址检测和平台要求。

不对称与对称 IRB 在入口/出口的路由和桥接处理、VNI与状态规模上不同。面试时先声明使用哪个模型，再描述报文，避免把两个流程拼在一起。

## 8. 故障案例：EVPN 邻居 up，但某一租户跨 leaf 不通

按层排查：

1. VTEP 源/目的可达吗？路径 MTU 是否支持封装？
2. 对应路由类型是否收到，下一跳是否可解析？
3. 租户实例 RT 是否导入，VNI 是否正确关联？
4. MAC/IP 是否映射到正确本地端口/远端 VTEP？
5. 主机 VLAN、掩码、网关、过滤与回程是否正确？

注入 RT 不匹配：邻居仍 up、全局 EVPN 表可能存在路由，但租户实例缺少所需导入。恢复 RT 后检查导入、FDB/路由与实际业务。与 underlay 故障对比：后者可能影响多个租户，而 RT 故障可局限某实例；这是线索，不是无需证据的定律。

## 9. 冗余和架构取舍

MLAG 通常以设备对提供跨机链路聚合；EVPN multihoming 使用 ESI 等控制面机制。DF 影响特定 BUM 转发行为，不能简单说“非 DF 不转任何流量”。多归属还要理解 split horizon、防环、批量撤销与接入设备行为。

L3 to server 可减少二层延伸和广播域，但要求主机侧路由/多路径与运维配合。EVPN/VXLAN 适合需要租户分离、网关和特定二层服务的场景。不要因为技术更新就默认把所有应用延伸为大二层。

## 10. 作业与参考答案

必交地址/VNI/RT 台账；同子网完整包路径；跨子网对称 IRB 路径；RT 错误与 VTEP 不可达两个故障矩阵。虚拟平台只验证功能，不据此承诺 ASIC 性能或生产收敛时间。

自测：RD 相同是否代表同租户？答：不能，RD不是租户成员控制。Type5是否替代Type2？答：用途不同。BGP收到路由是否已可转发？答：还需导入、下一跳、数据面与主机。为什么1500内层IP不能默认放入1500 underlay？答：封装后外层长度增加。单流是否等于所有ECMP路径总容量？答：通常不是，受hash及单路径瓶颈限制。
