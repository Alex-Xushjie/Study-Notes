# HLD、LLD、PoC与验收

[返回本部分学习目录](../Engineering-Reference.md)

## 1. 四份材料回答不同问题

HLD描述目标、架构、边界、路径、故障域和取舍；LLD描述可实施的对象/参数与依赖；PoC验证关键未知；验收确认交付是否满足约定目标。厚度不是质量，不能把配置转贴称HLD，也不把演示ping称PoC完成。

| 文档 | 最少内容 |
|---|---|
| HLD | 需求/约束、方案对比、逻辑/物理图、风险与范围 |
| LLD | 地址/接口/ID、版本、路由/策略、身份/DNS、维护 |
| PoC | 假设、环境/能力、输入、步骤、预期、反证与结果 |
| 验收 | 需求到测试映射、原始证据、缺陷/例外与签认 |

## 2. 跟踪矩阵

每条需求给ID，关联设计对象和测试，结果分通过/失败/未测/不适用。因环境缺失无法测试应写未测，不合并进通过率。变更需求需更新设计和验收，不沿用旧截图。

## 3. 图的标准

物理图标链路、电源、机房与责任；逻辑图标VLAN/VRF、路由和隧道；业务图标正反路径、NAT/身份与DNS；故障图标共享依赖。资源/设备名称与台账可对应，避免同一对象多种别名。

## 4. PoC优先级

先验证最大风险：多厂商互通、所需事务/HA、峰值/尾延迟、私有DNS或端点。功能已由既有环境证明时不反复做无意义基础测试；新版本或新组合仍要回归。

## 5. 练习

选双出口、园区漫游或EVPN租户方案，写一页HLD、对象LLD、一项可推翻方案的PoC和验收矩阵。无需真实账号可交设计，设备能力与性能必须后续实测。
