# 事故响应、交接与恢复确认

[返回本部分学习目录](../Engineering-Reference.md)

## 1. 恢复业务与确认根因

先确认影响与范围，组织指挥、技术处理、业务确认和沟通，按预案恢复/降级。根因可能稍后确认，但事实与时间线从开始保存。网络、主机、安全和应用使用共同对象/时间窗，不各自只说“我这里正常”。

## 2. 交接卡

| 字段 | 内容 |
|---|---|
| 事件ID/时间 | 时区、首次发现、当前阶段 |
| 业务影响 | 用户/站点/channel/事务和范围 |
| 已确认事实 | 来源、时间、证据位置 |
| 未确认假设 | 区分实验与负责人 |
| 已做动作 | 对象、原值、新值、结果与授权 |
| 当前风险 | 临时绕行、失去冗余、容量或安全 |
| 下一步 | 可执行动作、停止/接管条件 |
| 恢复标准 | 谁确认、哪些指标与观察时间 |

## 3. 取证与动作

抓取必要短窗口，避免敏感数据全量复制。高负载Debug、清状态、重启、切双路或改时钟都可能扩大影响并消除证据；需要明确范围与已有预案，不现场无边界试错。

## 4. 恢复后

验证关键业务、拒绝/隔离、备路径、时间/身份服务、日志和资源。业务暂恢复但仍单路或有临时放宽策略，事件应注明降级状态，不宣布全部风险已消除。
