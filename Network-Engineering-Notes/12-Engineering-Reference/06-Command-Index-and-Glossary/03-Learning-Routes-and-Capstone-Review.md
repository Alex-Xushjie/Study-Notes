# 学习路径、深耕方向与综合评审

[返回本部分学习目录](../Engineering-Reference.md)

## 1. 广度与深度分开验收

广度是能识别对象、路径、依赖和求助边界；深度是能设计取舍、复现故障、形成证据并实施可恢复变更。全书读完不自动达到技术专家，后续用真实可复核成果逐步提高等级。

按此前职业定位，主线可从两组中选择：量化方向深耕组播/行情完整性、Linux低延迟、路径/时间测量；企业/能源方向深耕路由WAN/SD-WAN、混合云与身份安全。园区无线、安全VPN和自动化作为通用能力，AIDC先保持拓宽。一个阶段优先2–3个深耕主题，不同时追求全部生产级精通。

## 2. 能力证据表

| 等级 | 可交付 |
|---|---|
| 认识 | 用自己的话解释机制与边界 |
| 观察 | 找到正确状态/计数并说明限制 |
| 验证 | 固定环境做正常、失败与恢复 |
| 设计 | 对比方案、容量、故障域和验收 |
| 运营 | 受控变更、RCA、协作与持续改进 |

每项写环境、日期、版本、证据链接和未覆盖项。生产、实验、软件模拟、离线推演分开，不能用教材内容填成个人实施经历。

## 3. 一个学习迭代

选一个业务问题→读相关章节→画路径/假设→最小实验→单变量故障→报告/RCA→复盘缺口。时间按自身工作安排设定，不要求先重读IP/掩码等已掌握基础。只有缺前置概念时回补，Linux从组件和命令语义开始。

## 4. 综合评审题

任选双WAN混合云、园区身份无线、行情A/B与主机、EVPN多租户之一，交需求、HLD/LLD、容量/安全、PoC、实施/恢复、监控和RCA。另请评审提出一个能推翻方案的故障，现场用证据解释并改进。

## 5. 完成与维护

一份代表项目包含至少正常、异常、恢复和拒绝/完整性四类证据；未具备硬件条件的条目标待实测。版本/业务变化后更新支持矩阵，不无限扩文章而没有实践闭环。
