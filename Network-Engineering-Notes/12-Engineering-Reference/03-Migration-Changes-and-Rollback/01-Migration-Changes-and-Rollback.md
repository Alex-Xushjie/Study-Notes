# 迁移、变更与回滚方法

[返回本部分学习目录](../Engineering-Reference.md)

## 1. 变更是受控状态转换

描述当前状态、目标状态、中间态与失败态。新旧并行往往比最终架构复杂：双网关、双路由、NAT、DNS缓存、身份和配置所有权都有交互。先确认前后路径与中间态，再安排命令。

## 2. 必备步骤

1. 固定需求、目标清单、版本、输入与变更生成物。
2. 采集基线、备份、依赖和已验证恢复资料。
3. 检查权限、带外、窗口、业务联系人与N-1。
4. 前检确认身份/版本/实际状态仍匹配计划。
5. 最小代表范围灰度，按指标观察。
6. 后检通过才扩批，失败按预案停止/恢复。
7. 验证持久化、更新SoT/文档并清临时对象。

## 3. 回滚与前向修复

回滚恢复先前可用状态；有时数据格式/状态不可逆，需要受控前向修复。不能承诺所有升级可一键降级，也不把备份文件当已验证恢复程序。恢复的网络、DNS、证书和应用会话需协同。

## 4. 故障域分批

双核心、双Feed、双防火墙或双云接入不要同时变更。若两个系统共享模板或控制平台，分两次操作仍可能存在共同错误，需独立验证基线/计划。

## 5. 练习

给旧MPLS转Overlay或传统VLAN转EVPN列中间态、前缀来源、网关与回程。定义失败阈值和最后可安全回退点，明确超时后谁接管，不写无限重试。
