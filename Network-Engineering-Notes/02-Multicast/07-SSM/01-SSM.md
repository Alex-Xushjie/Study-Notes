# SSM频道模型与源发现

[返回组播学习目录](../Multicast.md)

## 1. 从G转向(S,G)

Source-Specific Multicast要求接收者明确指定S和G。网络直接沿朝S的路径建立树，不需要ASM的RP汇合与Register源发现。IPv4标准范围232.0.0.0/8内的频道由(S,G)标识，不应按普通ASM只Join组。

这不是“只允许一个发送者存在”。S1和S2可以向同一个G发送，(S1,G)与(S2,G)是不同频道。接收者需要谁就显式订阅谁；若订阅错误源，网络完全正常也不会交付期望数据。

## 2. 源地址从哪里来

SSM把源发现放到应用/管理层，例如频道目录、配置中心、服务发布或协议握手。目录至少记录源地址、组地址、端口、业务频道、环境、启停时间和所有者。源地址切换应与订阅变更协调，不能只迁移发送服务后期待旧(S,G)自动跟随。

源地址选用稳定服务地址时，要验证故障迁移后的单播/RPF、地址唯一性与接收端过滤。Anycast源、NAT与多活源需要专门设计，不因共享地址就自动保序或自动无损。

## 3. 端到端要求

| 环节 | 检查点 |
|---|---|
| 应用 | 使用支持指定源的成员API，订阅精确S/G与正确接口 |
| 主机 | 实际发出含源集合的IGMPv3报告 |
| 接入交换机 | 正确处理v3及相关源过滤，不误删成员 |
| LHR | 将指定源需求转换成朝S的Join |
| 中间路由器 | SSM范围一致，源RPF与PIM邻接正常 |
| FHR/源 | 源地址与目录一致，TTL、业务出口正确 |

SSM不用RP，不代表不用IGMP/PIM或单播路由。看到配置里存在RP也不意味着该SSM业务依赖RP；按G所属范围与实际状态判断。

## 4. IGMPv2兼容不是原生SSM

部分设备提供SSM Mapping，把旧主机只报G的需求静态映射为(S,G)。这是一种兼容桥接，需要源映射维护；无法从旧报告自动知道应用真正想要哪个S。多个源、迁移和安全边界更复杂，应在设计中标明转换点。

## 5. 学习检查

两源向同一G和端口发不同标识，R只订阅S1：确认应用不接收S2；再增加S2订阅，观察是否同时收到。离开S1后S2应继续。测试源目录改错、源地址迁移与版本降级，记录每次源集合和Join变化。

[SSM定义：RFC4607](https://www.rfc-editor.org/rfc/rfc4607.html)、[IGMPv3/MLDv2的SSM行为：RFC4604](https://www.rfc-editor.org/rfc/rfc4604.html)。
