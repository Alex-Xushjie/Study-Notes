# ASM到SSM迁移与频道运营

[返回组播学习目录](../Multicast.md)

## 1. 迁移先查应用

从网络看SSM更少依赖RP，但应用可能仅支持任意源加入、硬编码旧组地址，或源服务会在多网卡间变化。先做能力清单：客户端API、操作系统、虚拟化/容器网络、Snooping、LHR、跨域承载与监控工具。不能只在路由器把239段声明成SSM就宣布迁移完成。

推荐另分配标准SSM频道，在并行阶段维护ASM与SSM的映射。并行会增加带宽和复制资源，尤其同一主机同时接两份时需明确是否去重及如何核对内容。

## 2. 分阶段切换

1. 建立业务频道目录，确定源服务地址、G、P及版本责任人。
2. 在测试域启动SSM源与接收者，验证正确源、错误源、源迁移和故障恢复。
3. 选小规模客户端灰度，比较序列号、延迟与主机资源。
4. 扩展并记录剩余ASM订阅，保持可回退的旧服务。
5. 确认没有旧依赖后，按窗口撤旧频道和相关RP配置。

最后一步只清理真正不用的组范围。RP可能仍服务其他ASM业务，不可因一个项目迁移就整域移除。

## 3. 频道运营台账

| 字段 | 用途 |
|---|---|
| channel/environment/owner | 避免测试与生产重名、找得到责任人 |
| S/G/P、接口与VRF | 让应用、网络、主机用同一对象排障 |
| 峰值bps/pps与包长分布 | 容量与突发验证 |
| 源切换/订阅更新方式 | 避免源迁移后长期静默 |
| 序列空间/重置规则 | 正确识别gap、重启和重放 |
| 生效/退役时间、变更号 | 追踪遗留订阅和回滚 |

目录是配置依赖，需版本化、审计并可回退。错误源地址可能让整批客户端一起失效；双交换机不能保护配置中心的一次错误发布。

## 4. 安全与故障边界

只收指定IP不等于认证发送者，源地址可能被伪造。接入端源限制、可发送组范围、跨域边界与应用完整性校验仍需要设计。网络中某处执行源过滤不一定代表其他无关端口完全看不到该数据；保密需求不能依赖组播成员管理。

跨组织对接须明确谁维护源目录、切换通知与过滤规则。RFC8815建议跨域场景转向SSM，不应由此推导“所有企业域内ASM必须立即废除”。迁移收益要与已有系统兼容成本一起评估。

## 5. 验收产物

提交旧新频道对照、端到端能力矩阵、并行容量、灰度结果和回退触发条件。故意发布一次错误源目录到测试客户端，验证回退流程，而不只是测试正常配置。

[跨域ASM的退役建议：RFC8815](https://www.rfc-editor.org/rfc/rfc8815.html)。
