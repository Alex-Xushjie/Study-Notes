# IGMP成员管理、版本与查询器

[返回组播学习目录](../Multicast.md)

## 1. IGMP管什么

IGMP是IPv4主机与同链路组播路由器之间的成员管理协议，IP协议号为2。它表达接收需求，不负责跨路由器建树，不检测发送者是否活着，也不做应用授权。IGMP报文不使用UDP端口。

v1提供基本查询与报告；v2加入Leave与更明确的查询器选举；v3增加源过滤能力。新规范为RFC9776，替代RFC3376，旧设备文档引用3376并不等于该设备不支持v3。

| 事件 | 要点 | 排错问题 |
|---|---|---|
| General Query | 询问链路上的成员关系 | 哪台设备在发，版本与间隔如何？ |
| Report | 主机报告成员/源过滤状态 | 在哪个VLAN、接口看到？ |
| v2 Leave | 离开意图，通常还需最后成员检查 | 下游是否仍有其他接收者？ |
| v3状态变化报告 | 表达源集合或过滤模式改变 | 不能只搜索v2 Leave判断离组 |

v3报告发往224.0.0.22，v2报告发往被订阅的组，v2 Leave发往224.0.0.2；General Query常用224.0.0.1。抓包只过滤业务组G可能漏掉v3成员报告。

## 2. 查询器与DR分开理解

IGMPv2/v3通常由同链路最低IPv4地址的合格路由器担任Querier。PIM DR按另一套规则选举，常看DR Priority再看地址。最低地址查询器和最高优先级DR可能不是同一台设备，这很正常。交换机的Snooping Querier是否参加同样选举、源地址是否有效，要看实现。

报告触发与查询维持共同保持状态。没有稳定查询器时，刚启动的程序可能靠主动报告短时可用，之后交换机或路由器状态老化，造成“过几分钟就断”的现象。不要简单改成永久静态成员掩盖查询器缺失。

## 3. 定时器推导

IGMP常见参数有Robustness Variable（容错次数）、Query Interval（查询间隔）、Query Response Interval（应答时间）。组成员维持时间常按RV×QI+QRI计算。示例取2、125秒、10秒，得到260秒；这是参数推导，不保证实际断流恰好260秒。

最后成员处理使用专门查询与计时，和普通组成员老化不能混为一谈。缩短所有计时器会增加报文与处理压力，且可能因丢一次报告就误删成员。先判断业务要求，再设置参数并验证有损条件。

## 4. 版本兼容风险

有旧版查询器或主机时，兼容状态可能使源过滤能力退化。看到一个v3报告只能证明该报告使用v3，不能证明端到端Snooping、路由器和应用都按(S,G)保留状态。检查每个组件的实际模式和兼容计时。

## 5. 验证任务

在同VLAN放两个接收者，观察先后加入、一个离开、全部离开。每次保存Query/Report及相应端口状态。停掉查询器后记录何时老化，恢复后记录重新建立时间；仅在隔离环境执行。能解释“一个进程关闭但主机仍报告成员”——同主机其他Socket可能仍订阅。

[IGMPv2：RFC2236](https://www.rfc-editor.org/rfc/rfc2236.html)、[IGMPv3：RFC9776](https://www.rfc-editor.org/rfc/rfc9776.html)。
