# 丢包定位、抓包可信度与RCA

[返回组播学习目录](../Multicast.md)

## 1. 统一观察窗口

以某频道session内序号10001—10100缺失为例，同时收集源出口、核心分叉、接入出口、接收NIC、内核/Socket和应用日志。固定G/P及必要的S过滤，统一时区与时钟误差说明。累计计数器要保存起止值并相减，不能拿昨天累积的drop解释今天的一次gap。

| 观察 | 能支持 | 不能单独证明 |
|---|---|---|
| 源抓包含缺失序号 | 抓包点看到源数据 | 实际物理出口一定成功发送 |
| 上游有、下游无 | 问题可能位于两点间 | 记录器自身没有丢包 |
| 交换机出口drop增长 | 该出口发生丢弃 | 一定丢的就是目标频道 |
| NIC rx_missed等增长 | 接收路径可能有资源问题 | 所有NIC计数名字语义都一样 |
| Socket丢包增长 | 内核到应用接收有压力 | 上游网络完全没有同时丢包 |
| 应用gap | 业务缺少预期内容 | 必然是网络丢包 |

## 2. Linux只读观察

先确认实际网卡名称；下列工具的统计口径和权限随版本不同。

~~~bash
ip -s link show dev eth0
ethtool -S eth0
nstat -az
cat /proc/net/softnet_stat
ss -u -a -n -m -p
sudo tcpdump -ni eth0 -s 128 -w multicast-test.pcap 'udp and dst host 239.10.10.10 and dst port 5000'
~~~

eth0是占位接口；pcap写入当前目录，应在测试目录执行。截取128字节可能不含完整业务内容，根据序号所在偏移调整。nstat很多计数是主机级，不自动对应某Socket；softnet_stat是按CPU的十六进制字段，按内核文档解释，不能机械累加所有列当丢包。

停止tcpdump时保存其捕获/内核丢包统计。SPAN可能超订阅、复制方向导致重复；采集卡/磁盘也可能丢。接收机抓包加重CPU负担时，需用独立镜像、缩小过滤或更合适的记录方案做对照。

## 3. 案例：平均15%仍有gap

事实：开盘时一组主机出现gap，路由邻居稳定。假设A为出口microburst，B为接收线程消费不足。收集小时间窗队列丢弃、NIC/Socket增量和线程调度，按相同序号范围对齐。

若出口抓包完整、NIC无明显丢弃、目标Socket丢包增长，降低应用处理负载后同样输入恢复，支持B；仍需说明抓包可信度和其他变量。若队列drop与受影响出口、序号窗口一致，并能用同样突发复现，支持A。二者可能同时存在，不强行只选一个。

## 4. RCA结构

记录影响与时间线、已确认事实、候选假设、区分实验、根因及触发条件、临时恢复、永久修复、回归结果与未确认项。写清修复如何作用于根因。例如增加Socket缓冲只能吸收有限突发，长期消费速度低于输入仍会积压。

## 5. 练习

设计三个互不相同的故障：RPF入接口错误、Snooping成员误删、应用消费变慢。要求应用现象相似但证据链不同。每个案例至少写一个能推翻首选假设的观察，避免只收集支持自己的证据。
