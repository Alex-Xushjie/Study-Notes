# RP故障与冷启动验收

[返回组播学习目录](../Multicast.md)

## 1. 为什么不停流不代表RP冗余合格

已经切到SPT的流可能暂时不依赖RP数据路径。如果故障测试只保留既有源、既有接收者，很容易得到“倒换无损”的片面结果。新源注册、新组加入、旧状态老化后的重建，才会暴露更多依赖。

## 2. 必测矩阵

| 阶段 | 操作 | 观察 |
|---|---|---|
| 正常基线 | 旧源/旧接收者持续运行 | 树、序列号、路径与RP节点 |
| 故障稳态 | 停一个RP或撤服务地址 | 原流是否持续，是否重选RPF |
| 故障中新接收者 | 新主机加入已有G | 新分支是否建立 |
| 故障中新源 | 新S向原G或新G发送 | Register与源信息是否到达正确节点 |
| 冷启动 | 测试实例清空后重新运行 | 完整发现与建树能否重建 |
| 恢复 | 原RP返回 | 是否抢占/震荡、是否出现重复 |

清状态、停进程和撤路由只在隔离实验实例中进行；生产维护需按设备正式操作流程。教材没有通用clear命令，避免误清整个业务域。

## 3. 记录分段时间

设t0故障注入、t1故障被检测、t2路由/RPF改变、t3组播树重新建立、t4应用恢复连续序号。t4−t0才接近用户感知中断。t2−t1可以帮助解释路由收敛，但不能替代完整恢复。

跨机抓包若时钟未校准，不适合直接相减推导微秒时延；可在同一记录器测相对间隔，再单独说明采集精度与丢包风险。所有时间注明测量点。

## 4. 恢复后的隐患

RP回来后IGP可能把不同源/接收者重新吸到它。源信息协作异常时，恢复反而制造黑洞。还要比较配置一致性、RP集合成员、唯一节点地址和服务地址、SA/注册过滤以及两节点的路由视图。

一次重启成功不代表冗余覆盖分区。节点故障、节点间链路故障、IGP可达但控制进程失败，是不同故障。按业务要求明确可接受的中断、丢包与重建范围，再作验收。

## 5. 交付物

输出一份“旧流正常、新源失败”的RCA练习：先列事实，再画源注册到RP-A、接收者Join到RP-B的路径，指出缺少何种同步。若只修复IP路由而未验证源发现，不应宣布根因解决。

[MSDP源活动规范：RFC3618](https://www.rfc-editor.org/rfc/rfc3618.html)为Experimental；现网支持范围与过滤语义以设备版本为准。
