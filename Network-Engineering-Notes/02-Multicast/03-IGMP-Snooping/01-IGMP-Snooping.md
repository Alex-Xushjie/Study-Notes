# IGMP Snooping与二层复制

[返回组播学习目录](../Multicast.md)

## 1. 为什么路由器有成员，交换机还需要状态

普通二层交换机不能像学习源单播MAC那样，靠数据报文的目的组播MAC知道谁想接收。Snooping监听IGMP，把组/VLAN与接收端口关联，减少无关出口流量。它优化二层复制，不替代PIM，也不替代接收端成员报告。

典型表项至少包含VLAN、G、成员端口和老化信息；支持源过滤的平台还可能按(S,G)记录。另有组播路由器端口（mrouter port），用于把成员控制报文送向路由器并处理相关数据。路由器端口可能来自PIM/Query监听或静态配置，规则因平台不同。

| 端口角色 | 数据处理目的 | 失配结果 |
|---|---|---|
| 接收者成员口 | 给真正订阅者复制 | 漏学导致黑洞，多学造成额外流量 |
| 路由器口 | 连接组播路由与成员管理 | 漏学可能让上游不知道有人接收 |
| 普通无成员口 | 尽量不承载无关组播 | 泛洪策略可能仍使其收到数据 |

## 2. Querier与Snooping不是同一功能

仅开启Snooping不一定自动有Query。纯二层VLAN可能需要显式Snooping Querier；有三层网关时应确认它是否正常查询。把交换机设置为Querier也不代表它能够跨VLAN转发组播。

配置前写清本VLAN查询器IP、选举/备用、查询源地址、版本与成员老化。不要用0.0.0.0查询源的特殊行为作为所有设备通用方案；不同实现可能不接受或不参与选举。

## 3. 未知组播与特殊组

未知组播指没有匹配转发表的组播数据，设备可能泛洪、丢弃或按策略处理。启用“丢弃未知组播”前，测试源先于接收者、成员老化、控制面恢复、静态设备与协议保留组。链路本地控制组常有特殊处理，不能要求所有224.0.0.x都按业务成员表过滤。

MAC映射冲突、IP粒度与MAC粒度表项、硬件容量也影响结果。控制面显示两个组不代表ASIC能完全隔离它们。查看实际硬件资源、复制表与无成员端口计数。

## 4. 验证矩阵

用S、R1、R2和无成员端口X。R1加入后应确认R1收包、X无不必要业务；R2加入后再让R1离开，R2应保持；全部离开后按预期时序撤销。分别覆盖LAG、交换机间Trunk与MLAG路径，注意成员可能在逻辑聚合接口显示。

隔离实验中关闭查询器，记录表项消失后数据是泛洪还是丢弃。这个差异决定事故是“所有人被行情淹没”还是“业务断流”，不能只看功能已启用。

[IGMP/MLD Snooping考虑事项：RFC4541](https://www.rfc-editor.org/rfc/rfc4541.html)。它是Informational文档，具体平台行为仍需核对厂商资料与实测。
