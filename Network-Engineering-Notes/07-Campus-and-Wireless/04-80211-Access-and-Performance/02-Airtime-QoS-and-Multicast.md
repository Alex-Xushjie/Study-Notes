# Airtime、WMM与无线组播

[返回本部分学习目录](../Campus-and-Wireless.md)

## 1. 按空口时间思考容量

同样消息量，低速、重传多的客户端可能占用更多空口。教学简化：50个活跃客户端各需要2Mb/s有效业务，合计100Mb/s，不含管理、竞争和协议开销；不能用AP标称1Gb/s就断言绰绰有余。

Airtime公平性、最小速率和负载引导都有适用边界。提高最低速率可能改善某些开销，却会减少兼容/覆盖，必须先确认语音、IoT与边缘位置。

## 2. WMM和端到端QoS

WMM将业务映射到不同接入类别，影响竞争资源机会，不保证绝对优先或延迟SLA。客户端标记、DSCP到无线类别、AP到交换机及WAN映射需贯通。把所有业务标最高优先会破坏设计。

## 3. 广播/组播

传统无线组播常与单播有不同速率、确认和节能交付行为；某些产品使用组播转单播/可靠组播等优化，会增加复制量且可能影响应用假设。IGMP Snooping、AP策略、客户端节能和DTIM均需核对，不能把有线组播转发表直接当无线交付保证。

| 场景 | 要验证 |
|---|---|
| 视频/发现服务 | 组地址、速率、成员与跨VLAN代理边界 |
| 大量单播复制 | AP空口、复制规模与客户端数 |
| 节能终端 | 缓存、唤醒与业务延迟 |
| 访客隔离 | 发现/组播是否意外越界 |

## 4. 练习

同一频道分别测试一台和多台接收者，比较空口、丢包与应用；记录优化是否改变实际源/目的和复制方式。不要拿ping通证明mDNS或视频组播可用。
