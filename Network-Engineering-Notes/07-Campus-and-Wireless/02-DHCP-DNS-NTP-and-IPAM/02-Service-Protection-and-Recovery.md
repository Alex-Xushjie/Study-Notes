# 基础服务保护与恢复风暴

[返回本部分学习目录](../Campus-and-Wireless.md)

## 1. 边缘保护的前提

DHCP Snooping通过端口角色和报文检查维护租约相关绑定；DAI与IP Source Guard可利用绑定或静态信息防止相应欺骗。它们不是开关一开就不会出事，需要正确识别服务器/中继方向、静态终端、上联和绑定持久性。

| 场景 | 误配后果 |
|---|---|
| 上联误设不信任 | 合法DHCP响应可能被丢 |
| 终端口误设信任 | 非授权服务可能穿过边界 |
| 静态设备无绑定 | ARP或IP保护误封 |
| 重启丢绑定 | 存量终端未续租却突然不通 |

具体检查点与信任继承按NOS核对。信任端口仅表示该功能的处理角色，不表示这条链路整体安全。

## 2. 依赖冗余

双DHCP/DNS/AAA不代表客户端都会自动尝试和快速恢复，需核对客户端、Relay目标、服务器同步与超时。跨楼宇或跨WAN部署又引入路由与时延依赖。基础服务与管理网络不要全依赖同一个故障域。

## 3. 恢复风暴

停电后大量AP/电话/客户端同时上线，可能集中消耗DHCP地址、DNS QPS、AAA、证书验证和上联。平日平均负载无法代表冷启动。测接入到业务的分阶段时间，限制非关键设备同步重启。

## 4. 验收与练习

在隔离测试网完成服务故障切换、交换机重启后绑定恢复和静态设备接入。明确哪些阶段实际测量、哪些只推演。事故恢复时保存丢弃原因，再做最小范围修复，不以全局关闭保护当永久方案。
