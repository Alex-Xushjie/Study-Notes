# 员工、访客、BYOD与IoT分区

[返回本部分学习目录](../Campus-and-Wireless.md)

## 1. 角色决定授权

SSID只是入口标识，不等于身份或完整隔离。可按员工设备、个人设备、访客、IoT、运维等角色定义认证与访问，利用平台支持的VLAN/角色/ACL和网关策略落实。多SSID也带来管理帧开销，先确认是否需要独立SSID，不能每个部门都无条件新增。

| 角色 | 典型需求 | 边界 |
|---|---|---|
| 受管员工 | 企业应用与共享服务 | 身份/设备状态与最小访问 |
| BYOD | 有限办公资源 | 注册、设备能力与数据策略 |
| 访客 | Internet与明确外部服务 | 不访问企业/管理地址，用户间隔离 |
| IoT | 特定平台/控制服务 | 逐设备/类别白名单、生命周期 |
| 运维 | 管理平面 | 强身份、审计、独立入口 |

## 2. 认证方式的取舍

企业EAP、每设备/用户密钥、共享PSK、Portal各有边界。MAC地址可变且可伪造，MAB不是强身份；Captive Portal的用户同意/登录也不等于无线链路已加密。

动态授权返回VLAN/角色后，验证该VLAN真实存在、DHCP与上联完整且ACL生效。认证成功但授权未落地是常见故障。

## 3. 发现与共享

打印、会议投屏和mDNS常跨越用户/设备区，需要明确服务发现代理与访问策略。允许发现不等于允许任意连接，客户端隔离在有线回流/跨AP时也可能有范围限制。分别验证同AP、不同AP和网关绕行。

## 4. 练习

写员工/BYOD/访客/IoT到DNS、Internet、打印、管理的访问矩阵，包含明确拒绝。测试路径与认证缓存失效/重新认证后的角色变化，不只查看登录页面。
