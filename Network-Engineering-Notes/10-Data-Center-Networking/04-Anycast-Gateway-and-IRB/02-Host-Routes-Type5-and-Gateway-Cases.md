# 主机路由、Type5与网关故障案例

[返回本部分学习目录](../Data-Center-Networking.md)

## 1. 主机与网段不同

Type2可携带MAC/IP绑定，Type5表达IP前缀，二者可组合但不是互相完全替代。具体转发可能依赖路由MAC、Overlay Index或实现模型，不能只看“前缀已发布”就认为下一跳解析完成。

静默主机、ARP/ND学习、网关发现与主机移动会影响绑定。扩展到外部子网时，需明确哪些设备发布汇总/明细，避免多个来源互相反馈。

## 2. 常见案例

| 症状 | 区分证据 |
|---|---|
| 同子网通，跨子网不通 | 网关/VRF/L3VNI、IRB模型和安全 |
| 本地跨网通，远端不通 | 远端Type2/5、RT、下一跳和封装 |
| 某主机失败但同网段其他正常 | 主机绑定、ARP/ND、重复地址与系统 |
| 只有返回失败 | 出口VRF/前缀、网关和状态服务链 |
| 小包好大包坏 | 封装MTU和备用路径 |

## 3. 网关一致性

同逻辑网关身份、掩码/前缀、VRF与本地接入映射需一致。把Anycast MAC误用到无关域、重复地址或租户映射错误，会导致难定位的局部故障。配置生成应验证唯一与复用规则，而非单纯检查语法。

## 4. 练习

提交一条跨子网流的“接入—路由—封装—解封—出口—返回”表，并分别错L3VNI、RT与网关映射。故障注入只改隔离测试对象，保留原配置和恢复验证。

[Type5规范](https://www.rfc-editor.org/rfc/rfc9136.html)、[IRB规范](https://www.rfc-editor.org/rfc/rfc9135.html)。
