# 多归属故障矩阵与MLAG取舍

[返回本部分学习目录](../Data-Center-Networking.md)

## 1. 先确认支持矩阵

硬件、NOS、ES/LACP、IRB、主机Bond、孤儿口、网关和维护机制组成完整方案。某平台支持EVPN不代表支持目标多归属/对称IRB组合，更不代表不同厂商配置可直接互通。

## 2. 必测故障

| 事件 | 观察 |
|---|---|
| 单主机链路故障 | LACP重选、单流与已有会话 |
| 单Leaf故障 | ES撤销、远端路径、主机恢复 |
| 上联隔离但下联仍UP | 是否黑洞、保护机制和主机感知 |
| 控制面分区 | ES成员视图、DF/防环与数据 |
| 节点恢复 | 角色重选、旧状态清理和重排 |
| 非多归属孤儿端口 | 仅此Leaf可达的业务边界 |

## 3. 比较不是排名

MLAG常依赖厂商明确的双机同步/Peer设计；EVPN MH可通过标准化控制机制支持相应多归属，但带来协议/资源与支持复杂度。根据既有平台、运维、规模和失败行为选择，不因“标准”就省略PoC。

## 4. 维护

维护前排空流量、确认N-1和主机路径；升级时核对混合版本与恢复，不能同时改变两个接入节点。回滚需恢复数据/控制一致，而不只恢复配置文件。

## 5. 交付

输出支持矩阵、故障表、正常/异常/恢复状态和会话影响。软件FRR实验可验证部分控制/转发逻辑，不能证明真实交换机ES硬件容量、ASIC防环或主机板卡故障。
