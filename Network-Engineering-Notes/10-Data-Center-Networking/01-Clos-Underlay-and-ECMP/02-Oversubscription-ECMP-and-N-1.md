# 超卖、ECMP与N-1容量

[返回本部分学习目录](../Data-Center-Networking.md)

## 1. 先确定流量切面

超卖率通常比较某切面下行接入总量与可用上行，必须写清统计方向与范围。Leaf有32×25G下联、8×100G上联时名义800G/800G为1:1；失去一个100G上联后为800/700≈1.143:1。真实业务不一定同时满速，但不能把名义1:1当端到端无拥塞保证。

## 2. 单流与Hash

8条100G等价路不代表一个120G流会自动拆成多路。ECMP通常按相应流字段选择，隧道内外Hash、UDP源端口熵和平台支持影响分布。少量大流可能碰撞，聚合平均空闲也会单成员拥塞。

| 需求 | 验证 |
|---|---|
| 多租户/业务并发 | 不同大流与小流的映射和公平性 |
| 单链路失效 | 剩余容量、丢包与重排 |
| 单Spine失效 | 受影响路径与恢复峰值 |
| 扩容/恢复 | Hash变化、流迁移和回归 |
| 集中出口 | Border/服务设备是否成为瓶颈 |

## 3. 收敛与完整性

BFD、路由更新、FIB安装和应用重连是不同阶段。Hash改变可使路径时延/顺序变化；所谓Resilient Hash等机制按平台核对，不承诺全部会话无损。

## 4. 实验

用不同五元组和包长建立流量矩阵，采集每成员速率/队列/错误；软件路由可验证选路，硬件性能需专门环境。报告正常、N-1、扩容前后，不只选最好一组。

## 5. 交付

提交容量假设、最坏流量切面、保留余量和业务降级方案。增长率和峰值以历史/预测注明，固定70%之类阈值不能代替具体业务分析。
