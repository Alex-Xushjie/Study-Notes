# 应用SLA、分类与路径选择

[返回WAN与SD-WAN目录](../WAN-and-SD-WAN.md)

## 1. 决策链条

先识别业务，再确认路由可达的候选路径，再评估路径是否满足SLA，最后依据成本/偏好/负载选路并执行安全策略。各平台具体先后次序与缓存机制不同，但排障必须把这些问题拆开。

| 业务 | 主要关注 | 策略取舍示例 |
|---|---|---|
| ERP/交易交互 | 成功率、响应分位数、会话稳定 | 合格路径中优先稳定，不频繁抢占 |
| 语音/会议 | 丢包、抖动、端到端延迟 | 独立质量目标与拥塞保护 |
| 文件/备份 | 完成时间、吞吐、窗口 | 成本优先，可限速/错峰 |
| 管理/身份 | 可达、安全与故障时可用 | 独立保底，不能依赖唯一被管路径 |

阈值应来自应用要求和基线，不把某产品示例150ms/1%照抄成所有业务标准。RTT与单向延迟不能直接混用，抖动算法也需核对。

## 2. 探测要代表真实路径

探测到ISP网关只证明近端路径，探测公共DNS不证明总部ERP可用。每个目标说明服务位置、协议、请求内容、出接口与回包路径。若Probe可绕到另一条线路，链路A故障也可能被B“代答”。

主动探测适合低流量时持续观察，被动遥测更接近实际业务却可能在无会话时没有样本。小包ICMP与加密的大包业务经历的策略/队列可能不同，应设计应用合成测试对照。

## 3. 分类限制

按IP/端口匹配简单但可能覆盖多个应用；DPI识别可能要等待首批报文，并受加密、QUIC、CDN和签名版本影响。域名对象受DNS解析、TTL和共享地址影响，不能当成永久精确身份。

测试新会话最初走哪条路径、识别后是否迁移、旧会话是否固定，以及Unknown应用的兜底。策略命中计数需与具体会话关联。

## 4. 所有路径不合格时

明确选择“最不差路径继续”“固定备选”“阻断”“人工处置”中的哪种行为，且分别考虑Hard Down和Out-of-SLA。没有通用最佳答案：阻断可能保护敏感事务，也可能直接扩大中断。

例：A延迟更低但丢包高，B延迟稍高但稳定。若ERP只比较延迟，就可能一直选择体验更差的A。用真实事务成功率验证组合目标，而非单指标排名。

## 5. 练习

制作两线路四阶段质量表：A/B都合格、仅A不合格、都不合格、A恢复。预测每种业务新流与旧流路径，并用实际状态与会话抓包核对。写清规则优先级、兜底和恢复迟滞。

[DiffServ业务类别参考：RFC4594](https://www.rfc-editor.org/rfc/rfc4594.html)用于理解业务差异，不是应用SLA阈值标准。
