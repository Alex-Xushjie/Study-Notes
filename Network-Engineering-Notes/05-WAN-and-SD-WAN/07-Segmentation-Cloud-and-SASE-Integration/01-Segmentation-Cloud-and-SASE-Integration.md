# 业务分段、共享服务与安全服务链

[返回WAN与SD-WAN目录](../WAN-and-SD-WAN.md)

## 1. 路由隔离是起点

把办公、访客、服务器、OT/生产辅助、视频和管理放入不同Segment/VRF，可减少默认互通；但隔离对象、路由泄漏和安全策略必须一致。某平台把Segment叫VPN，不代表该对象本身等同IPsec隧道。

| 层次 | 要定义的内容 |
|---|---|
| 接入 | VLAN/子网、身份与设备归属 |
| WAN | Segment、可发布前缀、站点间拓扑 |
| 共享服务 | DNS、NTP、认证、更新、代理、监控 |
| 安全边界 | 防火墙、应用访问控制、日志与审计 |
| 管理 | 谁能管理设备、从何处进入、故障时如何恢复 |

不同Segment都需要DNS，不等于应该全网互通。把访问矩阵写到源区、目的服务、协议、端口、身份、返回路径与负责人，再选择路由互通及检查点。

## 2. 共享服务互通

Route Leaking让前缀可达，不自动提供最小权限；防火墙放行也不能弥补没有回程路由。重叠地址、共享DNS解析与源NAT尤其容易使日志失去业务归属。先明确地址唯一性，再决定泄漏、代理或转换。

Hub服务链会让分支间或云流量经过安全设备，需核对双向都经过同一状态域。默认路由可能绕开检查点，备路径也可能无对应策略。不要只验证正常路径上的拒绝行为。

## 3. SASE、SSE和ZTNA

SASE将连接与安全能力结合，SSE更聚焦云交付安全能力；具体套餐和功能因产品而异。ZTNA通常面向身份与上下文约束的资源访问，不等于给用户开放整个内网，也不保证承载任意UDP、组播或旧工业协议。

把“到安全PoP的隧道UP”“用户通过身份验证”“资源访问被允许”“真实应用可用”分开监控。PoP选址、身份提供方、DNS、代理、证书与TLS检查都可能成为新依赖。

## 4. 故障模式

PoP不可用时是换PoP、退回总部、绕过还是阻断，需要逐业务决定。Fail-open可能扩大暴露，Fail-close可能中断业务；由业务与安全负责人确定后落实为可测试策略，不让产品缺省值替团队决策。

远程用户接入与站点互联使用不同认证/路径，尽管可能共享安全平台。办公VPN与工业远程维护应明确各自审批、时间限制、可达资源和日志，不能一条全通隧道解决所有需求。

## 5. 练习

设计办公/访客/管理三区，共享DNS与身份服务。写允许与拒绝矩阵，并测试正常、单Hub失效和安全PoP不可达。提交双向路径图与拒绝日志，证明隔离在备路径也成立。
