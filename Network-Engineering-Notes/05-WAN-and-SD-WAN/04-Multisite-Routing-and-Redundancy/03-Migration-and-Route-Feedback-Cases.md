# 混合WAN迁移与路由反馈案例

[返回WAN与SD-WAN目录](../WAN-and-SD-WAN.md)

## 1. 案例：新旧网络互相成为回程

A分支还在MPLS，B已转Overlay，Hub同时连接两网。若Hub把两网所有路由双向重分发，B前缀可能绕回新网，被误认为从旧网学到；原路径撤销时遗留路由还可能递归绕行。

先画每个前缀的原生来源，不从配置命令开始。规则应表达：B原生前缀可从Overlay导入旧网，旧网导回Overlay时不能再次作为新来源。用精确白名单、来源属性/Tag与跨协议保留验证实现；单纯提高管理距离未必阻止反馈。

## 2. 迁移步骤

1. 清点流量依赖：DNS、NTP、目录、证书、监控、备份及业务。
2. 选择过渡互联点和允许互通的VRF/前缀，不到处打通。
3. 建立新网但暂不让全部流量优选，检查路由来源与回程。
4. 灰度一个站点/一个网段，比较应用与安全日志。
5. 演练新网故障及回退，再扩大范围。
6. 确认无遗留流量后撤旧配置，更新监控与文档。

## 3. 默认路由陷阱

Hub给分支发布默认路由可提供集中出口，但分支本地Internet默认路由又承载Overlay端点。服务与传输边界不清时，端点路由会被业务默认路由吸进隧道。明确端点可达路径及递归来源。

另一陷阱是备用站点误发更具体业务前缀，最长匹配会压过设计中的主路径属性。先查前缀长度，再查协议优先级与Overlay偏好。

## 4. 重叠地址与回退

并购或外包站点可能与企业内部地址重叠。NAT可以提供受控转换，但会影响日志、访问白名单、DNS和某些应用内嵌地址。建立转换台账和正反向测试，不用相同私网前缀直接互相泄漏。

回退需要恢复路由优先、NAT、安全策略、DNS及应用状态。只把网线接回旧设备，不一定恢复旧会话或地址。

## 5. 实验交付

准备A/B/H逻辑拓扑，记录每个阶段的收到/选中/安装/发布路由，注入明细撤销和错误默认路由。用真实会话验证回程。若环境只有Linux静态路由，可以证明路径逻辑，不能声称验证了某厂商Overlay防环。
