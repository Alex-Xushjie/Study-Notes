# 故障检测、会话保持与恢复切回

[返回WAN与SD-WAN目录](../WAN-and-SD-WAN.md)

## 1. 把失败分三类

Hard failure是物理或明确连通性失效；Blackhole可能接口仍UP但业务到不了；Brownout是仍可达却丢包、抖动或延迟恶化。仅依赖接口状态不能覆盖后两类。

| 机制 | 主要对象 | 不覆盖的范围 |
|---|---|---|
| 光口/接口状态 | 本地物理链路 | 远端应用和上游黑洞 |
| BFD/隧道探测 | 指定转发路径 | 所有应用依赖 |
| 路由会话 | 控制邻接及路由交换 | 每个数据路径质量 |
| 主动服务探测 | 特定目标与协议 | 其他目的及复杂登录链 |
| 被动应用遥测 | 已有业务体验 | 无流量时可能没有样本 |

## 2. 恢复时间拆解

总中断近似包含检测、状态判定/防抖、路由与策略更新、隧道/邻接建立、会话重建和应用恢复。教学假设检测1秒、策略0.5秒、应用重连2秒，总约3.5秒；若这些阶段并行就不能机械相加。

BFD参数更激进会增加压力与误判风险。探测可能优先级高于业务，出现“探测正常业务卡”；也可能低于业务而误报。检查路径、DSCP、包长及采样窗口。

## 3. 会话保持的条件

换线后公网SNAT地址变化，原TCP会话往往不能原样延续；双设备HA可能同步状态，也可能仅同步配置。即便私网地址不变，隧道重建、反重放、重排和防火墙路径都可能影响会话。

不要把“新连接能建立”写成“旧连接无损切换”。分别测试长TCP、短连接、UDP会议和应用登录，记录恢复是否依赖重连。

## 4. 恢复切回

Failback可能抢占回主线路，也可能保留现有会话到自然结束。恢复需要连续合格时间、最小驻留、迟滞或人工确认，防止边缘质量反复触发切换。故障与恢复策略应分别定义。

主链路恢复后流量集中回迁可能制造新突发。先恢复少量流量观察，再按业务窗口切回，对重要状态会话可安排自然排空。

## 5. 验收

分别做断线、上游黑洞、质量退化、控制进程失败和链路抖动。记录t0注入、t1发现、t2路径改变、t3新会话成功、t4旧业务恢复，并明确时钟误差。没有真实线路时标记逻辑模拟。

[BFD：RFC5880](https://www.rfc-editor.org/rfc/rfc5880.html)，结合[收敛测量教材](../../01-Routing-and-Switching/08-High-Availability-and-Failure-Detection/02-BFD-and-Convergence-Measurement.md)。
