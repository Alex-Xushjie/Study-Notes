# 上线、策略发布与控制平台故障

[返回WAN与SD-WAN目录](../WAN-and-SD-WAN.md)

## 1. ZTP不是零前置条件

Zero-Touch Provisioning减少现场手工配置，但仍依赖线路、DHCP/静态地址、DNS、时间、设备授权、控制节点可达与证书。现场至少需要电源、物理接线、设备资产信息和失败后的带外恢复能力。

准备上线前检查表：设备/站点唯一性、序列号归属、版本兼容、接口映射、Underlay地址/NAT、允许的控制流量、时间与证书、模板变量、回退镜像和联系人。不要把真实密钥、激活凭据或可复用令牌写进学习仓库。

## 2. 策略生命周期

“业务意图→匹配条件→候选路径→SLA→不达标动作→下发范围→执行状态”是完整链条。对象创建、策略激活、设备接收、数据面实际命中是不同阶段。

| 层次 | 常见错误 |
|---|---|
| 业务意图 | “关键业务”未定义应用/地址与负责人 |
| 模板变量 | WAN接口或网关绑定错站点 |
| 策略匹配 | 宽泛规则遮蔽后续精确规则 |
| 发布范围 | 测试策略误推全网 |
| 执行状态 | 平台显示任务完成但部分设备未安装 |
| 效果 | 命中了规则却走不满足回程的路径 |

## 3. 灰度与回退

先导出运行配置与业务基线，再在测试或少量非关键站点发布。提前定义应用成功率、延迟、路由变化和管理连通性触发条件。确认平台支持的事务、确认提交或自动回退机制；没有该能力时需要可达的独立恢复通道。

回退不仅撤模板，还要核对派生路由、隧道、NAT、安全服务路径与已有会话。平台配置版本和设备实际运行状态必须对应，避免手工修好后下次模板覆盖。

## 4. 平台失联演练

依次测试仅Manager不可达、仅控制节点不可达、证书过期模拟、DNS失败和全冷启动。每项分别记录已有转发、新流、新路由、新站点、Rekey、监控与变更能力。证书测试应使用隔离测试PKI，不修改生产时钟或真实信任链。

管理平台备份需要包含可恢复对象、授权/密钥处理与版本兼容，单有虚机快照未必满足产品恢复要求。明确灾备恢复后设备如何重新建立信任。

## 5. 交付物

输出上线Runbook、模板变量台账、策略发布流程、失败恢复流程和控制依赖矩阵。审批与审计属于实际组织流程；教材练习本身不替代生产变更授权。
