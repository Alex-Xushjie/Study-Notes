# CE–PE路由、防环与混合承载迁移

[返回WAN与SD-WAN目录](../WAN-and-SD-WAN.md)

## 1. CE–PE协议选择

静态适合小规模稳定边界，但故障检测与备用撤销需另设计；eBGP便于明确发布和过滤；OSPF可降低某些接入配置成本，却增加域边界、区域与路由类型理解要求。协议选择不能只按团队熟悉程度，还要看运营商支持与规模。

| 项目 | 双方需约定 |
|---|---|
| 地址/会话 | 互联子网、ASN、认证、BFD与计时器 |
| 前缀 | 入/出白名单、汇总、默认路由、最大前缀 |
| 选路 | 主备偏好、站点间回程、属性保留/改写 |
| 运营 | 维护撤路由、故障联动、变更与回退 |

## 2. 多宿主与反馈

站点双CE、多个PE或混合MPLS/Overlay时，CE可能从一侧学到路由，再从另一侧重新发布，造成反馈、绕行或黑洞。按“谁是这个前缀的权威来源”划定发布边界，使用精确过滤和明确标签/属性；单个Route Tag不一定跨所有协议/运营商保留。

Site of Origin是某些多宿主VPN设计防止路由返回原站点的机制，但需要相应平台与运营商配合，不能把它当成CE随意设置就生效的万能开关。

## 3. OSPF特殊问题

PE–CE OSPF属于专门的VPN场景，有域标识、路由类型和防环机制等要求；不能按普通LAN邻接的直觉推断所有远端前缀都是原来的区域内路由。排错需双方对照LSA与VPN路由转换，而不是只看邻接Full。

## 4. 迁移示例

旧网MPLS互通，新网在Internet上建立SD-WAN Overlay，迁移期两者并存。若每个站点同时向两网重分发全部路由，很容易出现站点A经MPLS到Hub再从Overlay回A的反馈。

先选迁移边界/过渡Hub，规定原生站点前缀、可导入来源和默认路由归属。对每站点列出前向/回程正常与故障路径，再灰度迁移。下线旧链路前检查DNS、管理、认证和未登记应用，不能只检查主业务。

## 5. 练习与验收

三站点A/B/H，A走旧网、B走新网、H双接入。写路由来源矩阵、过滤策略和N-1路径；注入一个站点前缀误发布，验证边界可阻断。比较两侧收到/选中/发布的前缀，不以一张拓扑箭头替代路由证据。

[PE–CE OSPF：RFC4577](https://www.rfc-editor.org/rfc/rfc4577.html)、[VPN机制：RFC4364](https://www.rfc-editor.org/rfc/rfc4364.html)。复习[路由重分发与防环](../../01-Routing-and-Switching/04-Routing-and-Forwarding/02-Redistribution-Summarization-and-Loop-Prevention.md)。
