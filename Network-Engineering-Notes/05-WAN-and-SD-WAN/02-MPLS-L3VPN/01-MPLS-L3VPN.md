# MPLS L3VPN的客户视角与逐跳转发

[返回WAN与SD-WAN目录](../WAN-and-SD-WAN.md)

## 1. 企业需要懂到什么程度

企业工程师不必先成为运营商核心网专家，但必须解释CE–PE路由交换、业务隔离与回程。PE使用VRF区分客户，VPN路由携带区分与分发信息，核心通过标签转发把业务送到出口。CE通常只看到IP路由，不需要直接运行运营商的标签分发协议。

RD用于区分可能重叠的VPN前缀，RT用于控制VPN路由导入导出。两者不能替代：RD不同不代表允许互通，RT相同也不等于所有安全策略自动放行。

## 2. 逐跳理解

分支CE把报文交给本地PE，入口PE按VRF路由决定远端VPN出口及封装；骨干转发到出口PE，出口PE再按相应VPN上下文交给总部CE。常见解释用外层传输标签与内层VPN标签区分用途，但真实标签栈可能因传输方式、倒数第二跳弹出、熵标签等不同。

| 层面 | 企业可观察 | 可能需运营商协查 |
|---|---|---|
| CE–PE | 会话、收发前缀、接口与下一跳 | PE VRF是否学到CE前缀 |
| VPN分发 | 远端业务是否有路由 | RT、VPN路由、标签/隧道状态 |
| 数据转发 | 端到端与分段业务测试 | 核心丢包、标签转发、出口队列 |

## 3. 常见误解

MPLS不是加密算法，私网地址不是数据保密保证。核心设备不一定保存每个客户前缀，但PE需有相应VPN状态。ping本地PE成功只证明接入的一部分，不证明VPN分发、远端CE或应用可达。

客户默认路由可使未知目的进入VPN，但不代表允许把所有客户网段发布给运营商。按站点明确允许发布的汇总/明细，防止总部默认路由、Internet路由和重分发反馈污染企业WAN。

## 4. 互通边界

Hub-Spoke、Any-to-Any和共享服务是不同路由分发设计。分支间是否允许直接通信应通过VPN策略与安全边界落实，不能仅凭“都在同一家MPLS服务”推断。

运营商提供的L3VPN未必承载客户组播，需要专门服务能力。IP单播VPN能用不等于组播、广播或二层发现协议可直接跨站点工作。
