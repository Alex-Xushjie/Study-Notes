# 运营商接入、产品与责任边界

[返回WAN与SD-WAN目录](../WAN-and-SD-WAN.md)

## 1. 先把一条“专线”拆开

专线是采购用语，可能指Internet专用接入、点到点以太网、MPLS L3VPN接入、云连接或波长服务，转发与隔离能力并不相同。不要把产品名称直接当成网络机制。先确认交付的是二层还是三层、互联地址归属、是否经过公网、谁维护路由以及是否加密。

| 服务形态 | 客户通常拿到什么 | 必须追问 |
|---|---|---|
| Internet专用接入/DIA | 公网连接与约定带宽 | 地址、BGP/默认路由、DDoS、出口拥塞 |
| 二层以太专线 | 两点或多点二层承载 | VLAN、MTU、MAC规模、环路边界 |
| MPLS L3VPN | 运营商VRF内的三层互通 | CE–PE协议、路由范围、QoS映射 |
| 宽带/蜂窝 | 尽力而为的IP接入 | 上下行、CGNAT、流量上限、动态地址 |
| 云连接 | 到指定云接入位置/网关 | 接入点故障域、云侧路由、网关与带宽计费 |

MPLS VPN提供逻辑隔离，不天然等于端到端加密。SD-WAN可以把多类服务作为Underlay，但不会把廉价接入的物理质量变成有保证的专线。

## 2. 物理与管理交界

CE是客户边缘设备，PE是运营商边缘设备。运营商可能提供接入终端/NID或光猫，企业CE可能是路由器、防火墙或SD-WAN Edge。画图时标出光纤、机房入楼、ODF、接入终端、交接网口与CE，并说明每段由谁供电、监控和更换。

服务到交接口正常，不等于应用端到端正常；反之企业CE故障也不应直接报运营商线路故障。需要双方认可的测试端点、工单联系人、回环/测试权限和维护窗口。

## 3. 地址和NAT影响

公网静态地址有利于固定对端；动态地址和CGNAT可能要求主动建连、NAT穿越或经Hub中转。两条蜂窝链路即使不同SIM，也可能共享同一无线站点、回传或核心网。链路运营品牌不同也不证明物理光路独立。

采购资料应标明公网IPv4/IPv6、入站能力、NAT保活限制、MTU、允许的隧道协议，以及故障时的地址变化。应用若绑定出口IP白名单，线路倒换会同时成为访问权限问题。

## 4. 企业与能源场景

总部/数据中心看容量与多故障域；分支看部署、恢复与本地运维能力；偏远能源站点还需评估断电、蜂窝覆盖、恶劣环境、远程管理与现场备件。生产控制、办公和视频必须由业务风险与分区要求决定互通，不能因为在同一个WAN就默认互相可达。

具体电力/工控专网要求由适用规范和组织制度确定，本章不把通用Internet SD-WAN当作所有控制业务可接受的承载。

## 5. 练习与交付

为一个总部、两分支和一个偏远站点填写服务台账：电路编号、交付层次、速率、责任边界、地址/NAT、MTU、路由、监控、SLA与物理路径证明。把“运营商声称双路由”拆成可验收的入楼、管道、机房、供电和PE差异。

[运营商VPN术语：RFC4026](https://www.rfc-editor.org/rfc/rfc4026.html)。
