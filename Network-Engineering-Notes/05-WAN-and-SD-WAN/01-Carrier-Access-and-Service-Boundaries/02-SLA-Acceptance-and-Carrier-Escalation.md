# SLA、交付验收与运营商协同

[返回WAN与SD-WAN目录](../WAN-and-SD-WAN.md)

## 1. SLA不是单一可用率

合同SLA需要说明测量对象、起止点、统计窗口、排除项、阈值、通知与赔付。网络SLA与应用SLO（业务目标）有不同边界：线路满足延迟目标，应用仍可能因DNS、身份服务或服务器负载失败。

| 指标 | 必须澄清的口径 |
|---|---|
| 可用率 | 何时算不可用，是否包含维护和部分故障 |
| 时延 | 单向/往返，测量端点，平均/分位数 |
| 丢包 | 方向、报文大小、频率、统计窗口 |
| 抖动 | 使用哪一种时延变化定义，不能只比较同名数值 |
| 带宽 | 端口速率、承诺速率、峰值速率与上下行 |
| 修复时间 | 计时从故障发生、报障还是工单受理开始 |

教学计算：按30天、每月99.9%可用率计算，理论不可用预算约43.2分钟。它不是“每次故障允许43.2分钟”，也不自动包含全部排除项。

## 2. 验收分层

先验收光功率/链路协商、错误/丢弃、VLAN与MTU，再验收三层地址、ARP/ND、路由、QoS与吞吐。最后验证真实业务和故障切换。测试速率与生产共用链路时须限制负载；不要在办公时间直接满速压测。

吞吐测试明确TCP/UDP、单流/多流、窗口、端点CPU、双向负载及是否开启加密。端口1Gb/s不代表能得到1Gb/s应用有效载荷，单TCP流更不能单独证明线路全部容量。

## 3. 报障证据包

记录电路与站点、时区、故障起止、影响方向、源/目的测试点、接口差值计数、路由与探测结果。保留正常对照与拓扑。运营商侧测到交接口正常时，继续从CE到实际服务拆段，而不是重复争论“ping通/不通”。

公网traceroute中间节点不响应或延迟大，不一定代表它丢转发业务；可能限速控制面应答。终点与后续节点、双向测量、真实业务证据更重要。回程可以不同，单向路径图不能描述整条会话。

## 4. 维护与共同故障

双运营商可能共用最后一公里或同一施工区域。维护通知要映射到实际电路、Hub、云接入点和业务，而非只按供应商名称判断。故障演练覆盖物理断路、上游黑洞和质量下降，不能只拔一根CE网线。

## 5. 交付练习

写一份验收计划和一份报障单。给出可接受/不可接受标准、负载、测量工具、原始日志、双方签认和回退。将“平均时延合格但P99超标”作为争议案例，先查合同口径，再决定技术与商务处置。

[单向时延度量：RFC7679](https://www.rfc-editor.org/rfc/rfc7679.html)、[丢包度量：RFC7680](https://www.rfc-editor.org/rfc/rfc7680.html)。
