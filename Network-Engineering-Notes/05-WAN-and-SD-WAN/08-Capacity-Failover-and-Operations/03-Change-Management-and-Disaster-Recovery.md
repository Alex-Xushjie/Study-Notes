# 变更、升级、灾备与故障演练

[返回WAN与SD-WAN目录](../WAN-and-SD-WAN.md)

## 1. 变更范围控制

WAN配置可能跨站点传播，一个错误汇总或默认路由会影响整域。模板变更先列受影响对象、依赖版本、接口映射、预期路由差异和自动化校验，再分批发布。小站点成功不代表双Edge/特殊VRF站点也兼容。

变更包包含当前运行状态、期望差异、验证、回退触发和负责人。预先确认带外管理和现场恢复能力，避免断开唯一远程入口后才寻找Console。

## 2. 升级不是单设备操作

管理、控制、编排、Edge与安全功能可能有版本兼容矩阵和升级顺序。按厂商正式文档核对，保存配置、授权、证书处理与恢复镜像。新功能、缺陷修复和已知问题要映射到实际业务，不只看“版本更高”。

先验证配置转换、策略命中、HA、隧道和Rekey，再扩大批次。回滚可能涉及数据库或配置格式限制，不承诺所有升级都可一键降级。

## 3. 灾备资产

| 对象 | 需保留 |
|---|---|
| 管理/控制平台 | 支持的备份、恢复步骤、兼容版本与账号 |
| 边缘 | 配置/模板变量、身份归属、备用设备和接线图 |
| 承载 | 电路编号、联系人、地址与路由约定 |
| 安全 | 证书生命周期、密钥保管、身份服务依赖 |
| 业务 | 优先级、降级模式、恢复验证人 |

敏感材料按组织制度存储，不放进公开笔记。备份成功需要通过隔离恢复演练确认，不能只看定时任务绿色。

## 4. 演练覆盖

至少覆盖单线路断、接口UP但上游黑洞、质量退化、单Edge、Hub、控制平台、DNS/时间依赖和区域断电。并发故障需按实际目标选择，不无边界追求测试数量。

分别测“已有流”“新流”“新路由”“新站点”“长时间失联后恢复”。定义停止条件与恢复顺序，记录未覆盖的物理和云故障域。

## 5. 复盘

演练后核对实际恢复业务与文档目标、告警是否及时、工单是否准确、回退是否可执行，以及配置/监控是否留有临时修改。每个问题指派责任与复测条件。

练习输出一页Runbook：故障识别、影响判断、证据、允许的恢复动作、回退和业务确认。避免写成几十条无解释命令，值班人员必须知道每步目的与失败后分支。
