# 可观测性、分层排障与RCA

[返回WAN与SD-WAN目录](../WAN-and-SD-WAN.md)

## 1. 一条业务贯穿六层

固定源/目的、应用、VRF、时间窗与会话，再检查LAN接入、Underlay、隧道/加密、Overlay路由、选路/安全策略、应用依赖。统一时间与站点ID，保存配置版本；没有这些标识，平台曲线和用户报障很难关联。

| 层次 | 核心证据 |
|---|---|
| 物理/接入 | 端口错误、丢弃、协商、线路/NAT变化 |
| Underlay | 端点路由、网关、双向探测和MTU |
| 隧道 | 对端、SA/会话、封装收发、BFD和丢弃 |
| Overlay | 收到/选中/安装的路由、下一跳可达 |
| 策略 | 匹配规则、候选路径、SLA、NAT与安全日志 |
| 应用 | DNS、身份、TCP/TLS、事务结果和服务器资源 |

## 2. 症状到区分证据

隧道UP但无流量：查路由、选择器、策略、入隧道计数和回程；只大文件失败：查MTU与TCP，不先重启；控制平台在线但分支互访失败：查实际数据隧道、分段和NAT；每天固定时段卡顿：对照备份、队列与CPU，不凭平均利用率排除拥塞。

对端解密计数为0时，比较本端加密后是否真正离开、路径是否丢、对端是否匹配正确SA。单个大累计数无意义，应采样差值并对齐测试流。

## 3. 监控分级

组件健康监控设备、进程、隧道；路径监控质量与容量；业务监控真实合成事务和成功率。告警按站点/业务依赖关联，避免一条链路断导致几十个隧道重复呼叫，却遗漏关键应用不可用。

保留正常/异常基线、策略变更和版本升级事件。探测频率与存储粒度不一致时，小窗口故障可能在分钟聚合中消失；说明数据粒度限制。

## 4. 只读Linux端点检查

Linux新手先明确：ip查看系统网络状态，ss查看Socket，curl测试HTTP事务，tcpdump捕获指定接口上的报文。以下地址为实验私网，eth0需替换。

~~~bash
ip -br addr
ip route get 10.20.0.10
ss -t -a -n -i
curl --connect-timeout 3 --max-time 10 -o /dev/null -sS -w 'connect=%{time_connect} total=%{time_total} code=%{http_code}\n' http://10.20.0.10:8000/
sudo tcpdump -ni eth0 -c 100 'host 10.20.0.10'
~~~

curl字段是该事务时间点/总耗时，不能直接称为纯WAN时延；本地无该服务时失败属于前置条件未满足。抓包限制对象和数量，避免捕获无关业务。

## 5. RCA练习

案例：主线质量恶化，SD-WAN切到备线后ERP仍失败。至少提出三种解释：备线公网IP不在白名单、回程仍经原Hub、防火墙旧会话未迁移。给出区分实验、恢复方法与根因修复；“切换到备用”只是动作，不是根因。
