# WAN分阶段实验与企业综合设计

[返回WAN与SD-WAN目录](../WAN-and-SD-WAN.md)

## 1. 分清三档实验能力

第一档用Linux/FRR验证路由、回程、故障注入与MTU；第二档用合法授权的厂商镜像验证Overlay、SLA与策略；第三档用真实线路和设备验证物理故障域、吞吐、加密和运营。软件模拟完成不代表已证明第三档。

Linux实验前先阅读[系统与命令基础](../../03-Linux-Networking/01-Linux-Essentials/01-Linux-Essentials.md)。本篇不自动创建收费云资源、购买授权或连接生产WAN。

## 2. 最小逻辑拓扑

分支B连接模拟运营商A/B，再到总部H；B/H各有业务主机。先只用隔离虚机/命名空间准备拓扑，地址由实验者配置并保存台账。

| 网段 | 地址建议 | 用途 |
|---|---|---|
| 分支LAN | 10.10.0.0/24，网关.1，测试机.10 | 测试源 |
| 总部LAN | 10.20.0.0/24，网关.1，测试机.10 | 测试服务 |
| B–ISP-A | 172.20.1.0/30，两端.1/.2 | 模拟承载A |
| ISP-A–H | 172.20.2.0/30，两端.1/.2 | 模拟承载A |
| B–ISP-B | 172.20.3.0/30，两端.1/.2 | 模拟承载B |
| ISP-B–H | 172.20.4.0/30，两端.1/.2 | 模拟承载B |

这是路由实验地址，不直接复制到现网。基础档允许静态路由转发业务；真正Overlay档中，模拟ISP只负责端点可达，企业LAN前缀通过隧道/Overlay承载，不把LAN路由直接加入ISP来冒充隧道成功。

## 3. L1：路径、回程与长连接

完成接口、主机网关、路由和转发前置条件后，逐跳验证，再测试真实HTTP与长TCP。Linux测试服务可在总部测试机使用空的临时实验目录运行：

~~~bash
python3 -m http.server 8000 --bind 10.20.0.10
~~~

此命令把当前目录通过HTTP暴露给可达端点，只在隔离测试机的空目录运行，按Ctrl+C停止。分支可用上一篇curl示例测试。服务器绑定失败先查地址与占用，不将其误报为WAN故障。

分别记录A优先/B优先时的双向路径，手工改变路由验证回程影响。手工切换只证明路径逻辑，不是SD-WAN自动SLA选路。长连接需另用合适的测试应用，HTTP短请求成功不证明会话保持。

## 4. L2：质量退化与MTU

在专用模拟ISP的指定出口注入延迟/丢包，不能选管理接口或共享宿主机物理网卡。先用ip -br link识别网卡，用tc qdisc show dev接口检查现有队列。qdisc是Linux出口排队规则；netem用于模拟网络质量。

下面lab-wan-a是专门命名的实验出口，不存在时命令会失败，应在拓扑中明确创建/映射，不能随意替换成生产eth0。只有确认该专用接口没有需保留的自定义root qdisc，且保存初始状态后，才添加：

~~~bash
sudo tc qdisc add dev lab-wan-a root netem delay 80ms 10ms loss 1%
tc -s qdisc show dev lab-wan-a
~~~

80ms是这个出口方向额外延迟，10ms表示延迟变化参数，loss为模拟随机丢包；不是端到端最终测得SLA。如果只在一方向加80ms，RTT变化与双方向各加80ms不同。命令失败就停止排查，不用replace覆盖未知配置。

仅在本次add成功且初始无须保留自定义root qdisc的同一专用接口上，实验后撤销本次规则：

~~~bash
sudo tc qdisc del dev lab-wan-a root
tc qdisc show dev lab-wan-a
~~~

对比初始状态及业务恢复。若已有队列配置，另建独立实验接口/虚机，不用此简化撤销法。降低MTU的实验同样先记录原值与精确对象，按03专题测试大小包并恢复，不在本手册给共享设备一键改全局值。

## 5. L3：原生SD-WAN策略

在目标厂商实验环境建立单分支双传输与Hub。先查控制、数据隧道、业务路由，再配置一个明确定义的测试流、SLA与兜底。可先按IP/端口匹配避免DPI不确定性，再增加应用识别测试。

| 阶段 | 注入 | 必看结果 |
|---|---|---|
| 基线 | 两路径健康 | 实际会话、规则和出口 |
| Brownout | A加延迟/丢包但接口UP | 采样窗口、判定与搬流 |
| Hard Down | 测试路径A中断 | 检测、备用、旧/新流差别 |
| 全部Out-of-SLA | 两路都降质 | 继续/回退/丢弃是否符合设计 |
| 恢复 | A恢复并观察稳定时间 | 迟滞、切回与会话影响 |
| 控制失联 | 仅隔离控制路径 | 旧流、新流、新路由与长时依赖 |

每次一个变量，保留时间线、版本、原值、实际状态和应用结果。核心指标是业务恢复，不能只截一张平台“绿色”界面。

## 6. L4：能源企业综合方案

教学需求：总部双Hub、两个数据中心、20个办公分支、5个偏远站点及一处云业务。办公包含ERP/会议/备份；偏远站点仅设受控遥测/维护需求，实际生产控制能否使用该承载必须另行评审。

交付物包括：物理故障域图、Underlay/Overlay拓扑、地址/VRF/路由矩阵、应用分类与SLA、不达标动作、共享服务/安全路径、N-1与区域故障容量、云侧回程、上线模板、监控和恢复Runbook。为现场无技术人员准备换机/接线流程。

至少推演五个反例：双运营商品牌但共管道、备线容量不足、控制平台失联后冷启动失败、本地出口IP变化被业务白名单拒绝、旧MPLS与新Overlay路由反馈。给出证据与改进，不以功能清单替代设计。
