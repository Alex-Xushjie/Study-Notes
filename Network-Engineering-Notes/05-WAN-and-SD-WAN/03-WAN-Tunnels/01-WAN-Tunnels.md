# WAN隧道、IPsec与NAT穿越

[返回WAN与SD-WAN目录](../WAN-and-SD-WAN.md)

## 1. 区分承载、封装与加密

Underlay提供隧道端点之间的IP可达；Overlay承载企业业务逻辑。GRE封装能承载多种协议但不提供机密性；IPsec提供相应安全保护；某些SD-WAN使用自有封装与密钥分发，不能假定每个产品都用传统IKE协商。

业务前缀走隧道，隧道外层目的地址则需要独立的Underlay路由。若把隧道端点本身的路由递归指回隧道，会造成自我依赖。维护好服务侧与传输侧路由边界。

## 2. IKE与ESP各做什么

IKEv2负责认证与协商等控制过程；IKE SA保护控制交互，Child SA承载相应IPsec数据保护。ESP负责数据封装保护，SA具有方向性。IKE正常不代表两个方向的数据计数都正常。

| 检查对象 | 需要确认 |
|---|---|
| 对端身份 | 地址/标识、证书链或预共享密钥、时间与有效期 |
| 协商 | 算法、组、生命周期与两端兼容 |
| 业务范围 | 路由、Traffic Selector、策略与NAT顺序 |
| 数据 | 双向加解密计数、重放/认证失败、MTU |
| 维护 | Rekey、证书更新、地址变化和断线恢复 |

不要在教材中固定一套“永久安全”的算法清单。实施按组织基线、最新平台支持及更新后的标准选项验证，例子不构成密码策略推荐。

## 3. NAT穿越

普通ESP使用IP协议号50，IKE常见UDP500；存在NAT时常使用UDP4500进行NAT-T。协议号50与UDP端口50不是同一件事。放行端口仍需核对双方策略、映射与会话生命周期。

运营商CGNAT可能阻止任意入站，两个分支直接建隧道不一定成功。产品可能采用主动建连、穿越机制或Hub中继；“控制平台在线”不等于分支之间已有直连数据隧道。记录公网/私网端点与端口映射，必要时测试地址变化与映射超时。

## 4. Route-based与Policy-based

Route-based通常用逻辑隧道接口和路由决定业务流量，Policy-based通过选择器/策略匹配进入保护范围；实际产品仍可能有选择器限制。两端即便隧道建立，也可能因子网范围不一致、先NAT后匹配或回程路由遗漏而单向。

DPD、链路探测、隧道内BFD和应用探测测试的对象不同。一个检测进程能联系到对端，不代表后方应用健康。按依赖层次规划检测，避免几个机制相互撤路由导致震荡。

## 5. 排障练习

依次检查端点可达、协商、选择器/路由、封装前流量、加密计数、对端解密与LAN出口。注入错误身份、缺失业务前缀、单向NAT、上游丢弃4500和Rekey失败，分别说明证据边界。

[IPsec体系：RFC4301](https://www.rfc-editor.org/rfc/rfc4301.html)、[IKEv2：RFC7296](https://www.rfc-editor.org/rfc/rfc7296.html)、[NAT-T：RFC3948](https://www.rfc-editor.org/rfc/rfc3948.html)、[GRE：RFC2784](https://www.rfc-editor.org/rfc/rfc2784.html)。
