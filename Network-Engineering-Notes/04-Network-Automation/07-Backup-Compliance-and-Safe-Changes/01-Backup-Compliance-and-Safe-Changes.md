# 配置备份、基线与可恢复性

[返回网络自动化目录](../Network-Automation.md)

## 1. 备份不是拿到一段文本

有效备份需确认设备身份、采集时间、平台/版本、配置范围、完整性、权限和恢复方法。running、startup、候选配置与平台数据库不同，备份对象应按实际NOS能力确定。备份命令成功不证明输出未截断或所有依赖已包含。

| 项目 | 需要说明 |
|---|---|
| 对象 | 哪台设备、哪类配置、逻辑实例/VRF范围 |
| 完整性 | 命令成功、分页结束、格式与大小合理 |
| 保密 | 密钥/口令/拓扑信息如何保护 |
| 版本 | NOS、驱动、采集器、Schema与时间 |
| 恢复 | 支持方式、外部依赖、业务验证与回退 |

## 2. 存储与命名

结果目录按run_id和稳定device_id组织，限制写入根目录，防止设备名中路径分隔符越界。受控存储可保留原文，公开教学仓库只用脱敏Fixture。散列校验帮助发现变化，不证明内容来自正确设备或没有敏感数据。

备份加密、密钥保管、权限和恢复测试缺一不可。Git默认不是秘密保险箱，私有仓库也不能替代凭据管理。

## 3. 差异要区分噪声

时间、计数器、自动排序、动态对象可能使文本diff持续变化。归一化可去除已证明无关噪声，但不能把ACL顺序、策略顺序或业务关键字段当噪声排序。保留原文与归一化版本的映射。

基线不是永远正确的旧配置，需有业务与版本依据。故障恢复中的临时变更要标注，避免下一次合规自动纠正把业务再次打断。

## 4. 恢复演练

在隔离同类版本设备上验证恢复，检查接口、路由、邻接、身份和真实流量。恢复全量配置可能重启或覆盖管理入口，按平台正式流程操作。没有设备时只可完成备份完整性与解析验证，不能宣称验证了可恢复性。

## 5. 练习

设计一台路由器的备份Manifest：device_id、version、scope、run_id、collector_version、hash、status、restore_reference。注入空文件、命令报错、截断和错误设备身份，要求备份任务明确失败而非覆盖最后一份可用备份。
