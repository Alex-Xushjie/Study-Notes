# 凭据、端点信任与审计日志

[返回网络自动化目录](../Network-Automation.md)

## 1. 凭据按运行场景提供

交互实验可用getpass，自动任务用组织认可的Secret Manager、短期身份或受控凭据注入。环境变量比写进脚本少一类泄露风险，但仍可能被子进程、诊断输出或错误报告暴露，不是秘密保险箱。

清单只保存credential_ref，代码按引用获取，不把Token/密码放URL参数、命令行或Git。最低权限区分只读采集、渲染与发布账户，并保留轮换与吊销流程。

## 2. 先确认目标身份

SSH核对主机密钥，HTTPS校验证书、CA与主机名。关闭验证会使自动化可能连接冒充端点。内网CA或设备换机有正规信任更新流程，不能让所有失败都走accept-all。

跳板、代理和重定向会改变凭据传输边界；API分页或Location头必须验证目标来源。不能从不可信Inventory自动读取任意地址再附加生产Token。

## 3. 审计什么

日志记录run_id、device_id、操作者/任务身份、阶段、时间、命令类别、计划/输入版本、结果与错误码。日志级别与保留需受控，禁止长期DEBUG/TRACE记录全部原文、认证头或业务响应。

| 对象 | 建议处理 |
|---|---|
| 密码/Token/私钥 | 不记录，发生泄露即轮换 |
| 配置备份 | 受控加密与访问审计 |
| 设备输出 | 最小必要采集、脱敏 |
| Diff | 审查前脱敏并验证未失真 |
| 错误堆栈 | 保留定位信息，清除秘密上下文 |

no_log减少Ansible输出泄露，不代表变量、外部工具、回调和生成文件都自动加密。Vault保护静态秘密，不自动隐藏所有运行期使用。

## 4. 输入不是命令

设备名、接口描述和API字段都可能来自外部。使用参数化客户端与白名单，不把输入拼进shell=True命令；配置文本也要限制控制字符与语法。目标清单和计划必须同时约束设备与操作范围。

## 5. 练习

用假Token构造一次失败，检查终端、报告、日志、Diff和CI Artifact是否泄露。若真实秘密已进Git，删除当前文件不足以清历史与缓存；按组织事件流程轮换并处理历史，不用教材里的假密钥演示替代真实响应。

[Ansible Vault](https://docs.ansible.com/ansible/latest/vault_guide/index.html)、[Python日志](https://docs.python.org/3/library/logging.html)。
