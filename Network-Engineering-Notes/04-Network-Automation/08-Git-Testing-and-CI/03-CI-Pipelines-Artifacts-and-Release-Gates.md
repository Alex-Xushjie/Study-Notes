# CI流水线、生成物与发布关口

[返回网络自动化目录](../Network-Automation.md)

## 1. CI与发布分开

CI持续检查代码和数据变化，CD/发布流程执行目标环境变更。代码检查通过不表示已经得到生产变更授权，也不证明设备基线没有变化。默认流水线先做离线验证，设备操作放到有明确目标与凭据边界的阶段。

推荐阶段：语法/格式→数据Schema/业务验证→解析与判断测试→离线渲染→Diff与范围检查→计划审查→实验/灰度→后检→分批发布。按实际项目简化，不为流程名词增加无意义任务。

## 2. Artifact绑定

输入快照、模板版本、工具依赖、目标清单、计划哈希、采集时间、前后状态与报告形成可追踪集合。审查通过的计划与执行内容必须一致，不能审查A却临时从最新SoT生成B直接下发。

计划超过有效期或设备状态变化就重新生成并验证。多人并行变更同设备需协调锁、版本条件或独占窗口，不假设Git合并解决了运行态冲突。

## 3. Runner与秘密

Pull Request可能来自不可信来源。离线测试Runner不持有生产凭据，发布身份短期化且限制目标与操作；网络访问、日志和Artifact同样受控。不要让任意分支代码借助自动注入的Token连接所有设备。

失败后CI日志需有足够上下文但无秘密。下载Artifact也应有权限与保留期限，Diff脱敏不能破坏审查者理解关键命令的能力。

## 4. 关口条件

| 关口 | 拒绝/暂停条件示例 |
|---|---|
| 输入 | 空/不完整Inventory、重复目标、未知平台 |
| 渲染 | 未定义变量、注入字符、超出所有权 |
| 计划 | 意外删除、大范围变化、非预期设备 |
| 前检 | 身份/版本/哈希不一致、备份或恢复通道缺失 |
| 后检 | 关键邻接/路由/业务失败或UNKNOWN |

生产审批依据真实组织流程，不能由一行approved=true替代。测试和发布记录反映真实执行，未运行设备步骤就标未运行。

## 5. 练习

为离线健康检查与配置渲染设计一条不访问设备的流水线，再画独立发布阶段及凭据边界。模拟输入被改、目标变化、后检UNKNOWN和部分失败，说明如何停止与保留证据，而非只让流水线一直显示绿。
