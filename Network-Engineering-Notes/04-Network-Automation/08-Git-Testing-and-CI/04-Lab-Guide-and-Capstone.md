# 自动化分阶段实验与综合项目

[返回网络自动化目录](../Network-Automation.md)

## 1. 阶段与前置条件

离线规则/解析→单设备只读→多设备报告→离线配置生成→实验变更→发布流程设计。没有设备也能完成前几阶段，不为学习购买生产授权或接入真实业务。Windows可完成标准库Python练习，Ansible控制端按官方支持准备Linux/WSL等环境。

每个练习记录Python/依赖、平台版本、输入和输出。示例标注的文档地址不是可登录设备，必须自己准备合法隔离镜像或硬件。基础阶段不要求把框架全部装齐。

## 2. A1：离线输入与规则

运行01专题的三个脚本，输入使用02专题inventory.json。测试正常、缺文件、坏JSON、错类型、重复设备及非法IP。注意不同脚本负责不同层级：count_inventory只检查顶层与计数，不提供完整清单校验；validate_device示例还需要vlan字段，不能把另一篇清单直接当同一Schema。

保存bgp_check.py与test_bgp_check.py，执行标准库测试。加入Idle、缺邻居、采集失败和不完整数据，确认不出现虚假全通过。

## 3. A2：已有可运行项目

现有[自动化项目](../../../Network-Career-Lab/02-Automation/02-Project.md)在Network-Career-Lab根目录提供：

~~~text
python labs/automation/health_check.py labs/automation/sample.json --output labs/automation/report.json
python -m unittest discover -s labs/automation -p "test_*.py"
~~~

先确认实际根目录与文件。health_check写入教学报告JSON/CSV，不访问设备；样例故意包含FAIL和UNKNOWN，因此非零退出码是预期结果，不应删掉异常记录追求绿色。标准库测试和模拟数据不能证明实机采集正确。

读取代码时找加载→验证→判断→汇总→退出码→报告，暂不扩展12项检查。先加接口或计数器一项，配健康/异常/缺失反例，定义数据单位与预期。

## 4. A3：单设备只读

使用03专题的Netmiko示例，先核对目标、只读凭据与SSH主机密钥。采集一个低负载命令，将原文、解析、归一化分层；分别测试错误认证、超时、命令拒绝与格式变化。不得把真实口令/配置提交到作品集。

拓展到多设备时先2台，再按设备和AAA容量增加并发。报告必须保留失败设备和阶段，不能只输出成功列表。采集时间和完整性用于后续健康判断。

## 5. A4：模板与离线Ansible

运行Jinja示例，测试缺变量、未知接口、换行字符与同输入两次一致。Ansible使用本地Playbook；现有项目另提供render.yml与教学模板，可按项目说明在隔离目录生成文件并重复运行。

Check/Diff、离线render与实际设备配置是不同验证。每个生成片段标明平台与输入版本，人工解释所有拟修改行。字段缺失绝不自动生成清空或删除。

## 6. A5：实验变更与部分失败

仅选一项低影响、明确所有权的实验描述变更。采集基线，固定输入/模板哈希，生成Diff并审查，单台执行，再做配置与业务后检；保留恢复原值的已验证方法。

随后模拟第2台失败、第一台已生效，记录各设备状态并停止后续批次。若环境无设备事务/Checkpoint能力，说明不能保证原子回滚，不以异常捕获代替恢复。

## 7. 综合作品：网络健康检查与受控生成

| 模块 | 必须交付 |
|---|---|
| 输入 | Schema、稳定ID、期望集合、来源/版本与完整性 |
| 采集 | 可替换Adapter、超时、信任、失败分类 |
| 判断 | PASS/FAIL/UNKNOWN/N/A与理由 |
| 输出 | 脱敏JSON/CSV、run_id与明确退出码 |
| 生成 | 严格模板、字段所有权、确定性Diff |
| 发布设计 | 范围、前检、灰度、后检、回退与授权边界 |
| 验证 | 离线反例、实机支持矩阵及未覆盖项 |

建议用现有项目逐步扩展，不一次重写成大型平台。最终能说明一个错误输入如何被拒绝，一个超时设备如何保留，一个错误计划如何在执行前被停止。

## 8. 结课自测

为什么采集空表不一定是健康？为什么API超时后不能直接重发写请求？为什么模板成功不代表设备接受？为什么Check Mode不是业务保证？为什么备份不等于可回滚？每题给出反例、观察点与限制。

使用[实验报告模板](../../../Network-Career-Lab/08-Portfolio/Lab-Report-Template.md)。文档、测试与作品集分别标记离线模拟、实验设备与生产经历；本次编写不自动连接或改动任何网络设备。
