# 二层与三层交界：完整报文路径和故障案例

[路由交换学习目录](../Routing-and-Switching.md)

## 1. 同子网与跨子网要分别画

同子网A访问B，A先取得B的链路地址，再向B发帧。跨子网A访问C，A交给所选网关MAC，IP目的仍为C；网关做三层查询、TTL处理和出接口二层重封装。无NAT时，普通路由过程不把IP目的改成下一跳。

~~~text
A VLAN100 → SVI/网关 → 路由/VRF → VLAN200 → C
~~~

至少标内层源/目的IP、当前源/目的MAC、VLAN、网关、VRF和回程。代理、隧道或NAT出现时另画边界，不能把变化混为同一类。

## 2. 三张表与四种状态

MAC表定位二层出口，ARP/ND把IP下一跳映射为链路地址，路由表定位三层路径。接口/生成树/聚合状态决定相应出口能否使用。三张表各自有记录，不代表它们已经组成同一条有效路径。

控制面可能保留状态而硬件表未正确编程；软件ping到设备CPU与经ASIC转发的业务也可能不同。观察目标应覆盖实际转发路径，不只访问管理地址。

## 3. 案例A：能ping网关，不能到同网段B

候选包括主机掩码、private VLAN/端口隔离、B过滤、重复地址与二层路径差异。网关在另一交换机或代理ARP时，ping网关并不覆盖A到B路径。双端看ARP请求/回应、MAC位置与标签，确认B是否真正收到。

## 4. 案例B：ARP缓存一清就暂时好

不要据此判内核缓存坏。调查重复IP、网关冗余切换、MAC漂移与邻居更新。保存故障前IP→MAC、交换位置与时间，再清理单个实验条目。全网清ARP会破坏证据并制造流量，不作为常规第一步。

## 5. 案例C：关闭一条聚合成员就恢复

支持“某条路径相关”的假设，但仍需定位标签、MTU、错误、聚合对端或hash。用多五元组与成员计数重复验证；不要把一个成功ping等同整条成员健康。

## 6. 安全与边界

DHCP Snooping、Dynamic ARP Inspection、IP Source Guard等接入保护会引入绑定与信任状态，误配可能导致ARP或地址获取异常。具体功能、数据源和trunk信任按平台核对，不默认把所有上联设trusted，也不为恢复直接关闭全网保护。

实验只在隔离VLAN注入错误。每次恢复后复核地址、MAC、路由与真实业务。没有实际设备时提交推演，不将软件模型当ASIC实测。

## 7. 输出

提交一份五跳以内的逐点报文账本，至少包含正常与故障时哪个状态发生变化、哪个证据否定了最初判断。跨层Linux观察可对照[网卡与普通路由](../../03-Linux-Networking/02-Interfaces-Routing-and-VRF/01-Interfaces-and-Routing.md)。
