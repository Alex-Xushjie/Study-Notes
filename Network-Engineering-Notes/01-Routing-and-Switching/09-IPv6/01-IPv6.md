# IPv6工程基础：地址、ND、RA与主机行为

[路由交换学习目录](../Routing-and-Switching.md)

## 1. 把IPv4经验映射而不是逐字照搬

IPv6地址128位，基本头40字节，没有IPv4广播交付模型，路由器不替源端执行IPv4式转发分片。Hop Limit对应逐跳寿命，扩展头与ICMPv6参与后续处理。[RFC8200](https://www.rfc-editor.org/rfc/rfc8200.html)

前缀与最长匹配的思想仍适用，但ARP、默认网关获取、邻居状态和防火墙不能原样照搬IPv4。

## 2. 地址与作用域

| 类型/例子 | 工程含义 |
|---|---|
| ::1 | 本机回环 |
| fe80::/10范围 | 链路本地地址，通信需明确链路范围 |
| 全局单播 | 按实际分配与路由使用，不因配置就自动互联网可达 |
| ULA，常见fd开头规划 | 本地用途地址规划，仍需要路由与安全 |
| ff00::/8 | 组播及相应作用域 |
| 2001:db8::/32 | 文档示例，不用于真实公网公告 |

同一接口可有多个地址，来源和有效期不同。稳定隐私/临时地址不应强行按MAC推导，旧EUI-64经验不能覆盖所有客户端。/64常见于以太网SLAAC；点到点等前缀设计另有条件，不把每类链路都机械设为/64。

## 3. ND不只是IPv6版ARP

Neighbor Discovery使用ICMPv6等机制：RS请求路由器信息，RA通告相关信息，NS/NA用于邻居发现/可达性等，Redirect提供相应转向提示。DAD用于重复地址检测，与确认默认网关可达不是同一件事。[RFC4861](https://www.rfc-editor.org/rfc/rfc4861.html)

Neighbor Cache与Destination/Prefix/Default Router等状态一起影响主机决策。STALE不等同立即失败，地址tentative/dadfailed也需与邻居问题区分。

## 4. RA、SLAAC与DHCPv6

RA提供相应默认路由器、前缀、标志与生命周期信息。SLAAC可根据前缀与主机机制形成地址；DHCPv6可提供地址/其他配置，但不能把IPv4“DHCP给默认网关”的模型直接套过来。

M/O等标志、RDNSS与客户端实现共同影响结果，不是一个bit就保证所有系统采取同一动作。地址已形成不代表有默认路由，默认路由有也不代表DNS已配置。[SLAAC RFC4862](https://www.rfc-editor.org/rfc/rfc4862.html)

## 5. 链路本地下一跳与接口范围

fe80::1可能在不同链路重复出现，查询/访问需要明确接口。Linux只读示例：

~~~bash
ip -6 address show
ip -6 route show
ip -6 neigh show
ping -6 -c 3 -I ens160 fe80::1
~~~

ens160与fe80::1必须是实际实验接口/邻居；-I明确相应接口条件。下一跳链路本地不表示没有全局路由，是常见设计。OSPFv3也常依赖链路本地邻接，细节与OSPFv2不同。

## 6. ICMPv6与安全

全局屏蔽ICMPv6会影响邻居发现和必要错误反馈。RA Guard、DHCPv6防护、ND保护等按信任边界与平台能力部署，不用简单permit-any或deny-all代替设计。

开启IPv6转发后，Linux接收RA的行为还可能变化，应查对应accept_ra等参数而非猜测。无意RA、地址生命周期错误和DNS信息不一致都可能导致间歇故障。

## 7. 验收

记录地址来源、默认路由、邻居、DNS与实际服务。分别模拟无RA、重复地址、DNS缺失和必要ICMPv6受阻，至少两个可用条件下复现。

自测：有SLAAC地址是否证明有默认路由？答：不保证。DHCPv6地址成功是否替代RA默认路由检查？答：不是。IPv6是否没有邻居解析？答：有ND。继续[双栈排错](02-Dual-Stack-and-Troubleshooting.md)。
