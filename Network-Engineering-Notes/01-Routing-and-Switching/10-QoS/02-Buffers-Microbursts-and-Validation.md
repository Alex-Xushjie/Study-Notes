# Buffer、Microburst与QoS验收

[路由交换学习目录](../Routing-and-Switching.md)

## 1. 队列怎样增长

当到达速率超过服务速率，积压增长。两路各8G同时进入10G出口，净积压6G；持续1ms产生约6×10^9×0.001÷8=750,000bytes。真实系统还涉及共享buffer、阈值、调度与包长，本算式只是数量级。

突发结束后可迅速排空，5分钟平均低并不能排除短时丢弃。采样不覆盖微秒级变化时，要结合水位、队列丢弃和更合适遥测。

## 2. Buffer与延迟预算

若某10G出口前实际等待1MB，简单排空时间约1,000,000×8/10^10=0.8ms，尚未加其他延迟。这说明“无丢包”可能通过更多等待实现，不代表低延迟目标达标。

动态共享buffer、专用headroom、阈值与计数单位按ASIC核对。不要把文档的总芯片buffer全部当成单端口可用容量。

## 3. ECN与丢弃

ECN通过相应标记使支持的端点反馈拥塞，响应与传输机制有关；标记多可能表示反馈生效，也可能表示持续过载，需看吞吐、丢包与尾延迟。[RFC3168](https://www.rfc-editor.org/rfc/rfc3168.html)

PFC/RDMA在其他专项展开，不把它当所有TCP网络的通用补丁。丢弃、暂停与应用性能应分口径记录。

## 4. 测试矩阵

| 场景 | 必看结果 |
|---|---|
| 无竞争基线 | 功能和负载生成器能力 |
| 多流竞争 | 类别匹配、带宽与时延 |
| 短时incast | 水位、丢弃、微突发关联 |
| N-1容量 | 关键业务是否仍达标 |
| 策略回退 | 是否恢复原基线与所有业务 |

固定消息大小、方向、并发、样本量和时长。只选最佳一次，或删掉超时样本再算p99，会误导结论。

## 5. 案例：语音好了，备份完全停滞

可能是受控资源分配的预期，也可能分类过宽让大量数据进优先队列。比较匹配计数和真实包，再检查调度。只有语音一项变好，不足以批准全网部署。

交付业务→标记→队列→调度→指标表与单变量对比。Linux端的socket/队列也可能成为瓶颈，参考[性能分析](../../03-Linux-Networking/09-Performance-Analysis/01-Performance-Analysis.md)。本文没有实际ASIC压测。
