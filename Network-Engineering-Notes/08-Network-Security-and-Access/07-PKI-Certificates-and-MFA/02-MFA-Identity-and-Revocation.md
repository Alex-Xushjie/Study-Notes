# MFA、身份提供方与撤权

[返回本部分学习目录](../Network-Security-and-Access.md)

## 1. MFA不是两个密码

因素通常区分所知、所持和生物特征等。密码加另一个密码不自动成为独立多因素。抗钓鱼能力、终端绑定、恢复与用户体验因方法不同；按组织安全基线选取，不把一次Push确认等同所有风险已消除。

SSO/IdP集中身份方便治理，也成为依赖。SAML/OIDC等不同协议和Token/断言验证需要正确受众、签发者、签名、时效和重放控制，网工需理解路径与故障边界，不手写简化认证器替代成熟组件。

## 2. 会话与身份期限

IdP登录、VPN隧道、ZTNA资源和应用各有会话。账号禁用不一定立即撤销全部缓存Token或已建立连接，需定义过期、刷新、撤权和强制终结机制。

| 事件 | 验证 |
|---|---|
| 用户离职 | 目录、活动会话、证书和例外访问 |
| 设备丢失 | 设备信任、凭据、Token与远程管理 |
| MFA设备更换 | 可信恢复与身份核实 |
| IdP故障 | 新登录、旧会话与受控应急流程 |
| 时间异常 | 断言有效期与终端/服务时钟 |

## 3. 最小权限与审计

身份组到资源授权要可追溯，嵌套组/缓存与动态角色更新都需测试。记录用户/设备/会话/资源/结果，不收集真实MFA码、口令或完整可复用Token。

## 4. 练习

用受控测试用户完成登录、过期、禁用和会话撤销，记录各系统实际传播时间。若只改目录但客户端仍可访问，应明确是哪层缓存或会话，不简单判网络策略失效。

[零信任身份与策略模型](https://csrc.nist.gov/pubs/sp/800/207/final)。具体MFA/协议实现查组织IdP正式文档；本篇不承诺所有产品即时撤权。
