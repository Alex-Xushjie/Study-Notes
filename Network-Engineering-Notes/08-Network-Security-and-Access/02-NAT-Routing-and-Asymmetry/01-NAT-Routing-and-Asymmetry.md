# SNAT、DNAT、Hairpin与路由

[返回本部分学习目录](../Network-Security-and-Access.md)

## 1. NAT不等于授权

SNAT改变源地址/端口，DNAT改变目的映射，PAT复用端口。它们解决地址呈现或互联需求，不替代防火墙授权、身份或加密。NAT前后查规则/路由的顺序由平台决定，必须明确用哪个地址匹配。

发布内部服务时，客户端访问公网VIP，边界把目标改为后端；返回通常需要同一状态域逆向转换。后端默认路由绕开边界，可能使用户看到不匹配响应或被状态设备丢弃。

## 2. Hairpin

内网用户通过公网域名访问内部服务时，可能需要Hairpin/NAT Reflection，或采用Split DNS给内网合适地址。两者有不同路径、日志与维护代价，不能仅因外网访问通就认为内网也通。

| 五元组位置 | 要记录 |
|---|---|
| 客户端发送 | 真实源、解析目标与端口 |
| DNAT/SNAT之后 | 后端实际看到的源与目的 |
| 后端返回 | 下一跳与是否回到状态域 |
| 用户收到 | 是否恢复成预期连接四元组 |

## 3. 重叠与例外

重叠地址互联需记录转换池、DNS、日志与应用限制；NAT Exemption常用于相应VPN场景，但按策略顺序和平台术语核对。误SNAT可能让VPN Selector不再匹配或丢失用户身份。

## 4. 练习

画Internet→VIP→后端以及内网→同VIP的双向地址变化，验证服务端日志与真实客户端归属。注入缺回程和错误规则顺序，不以“公网IP能ping”作为端口发布成功。

[传统NAT术语RFC3022](https://www.rfc-editor.org/rfc/rfc3022.html)、[UDP NAT行为RFC4787](https://www.rfc-editor.org/rfc/rfc4787.html)。具体平台和IPv6设计另核对。
