# 会话容量、端口耗尽与非对称路径

[返回本部分学习目录](../Network-Security-and-Access.md)

## 1. 带宽低也会失败

短连接数量、并发、目的地址集中度和超时影响NAT/防火墙资源。不能用每个公网IP固定支持某个连接数的简化结论套所有产品。相同端口能否对不同目的复用、保留端口与分配机制各异。

教学简化：每秒1000个新连接、平均状态保留60秒，可形成约60000个并发状态；真实连接复用、超时和清理影响结果。这不是产品上限，更不等于60秒内有60000个真实用户。

## 2. 双WAN与非对称

出站SNAT到ISP-A地址，返回可能固定进入A；失败后改B地址通常需新连接。私网路由切换即使保留原IP，也可能使回包经不同防火墙或跨HA节点，状态共享能力要验证。

ECMP、策略路由、SD-WAN和更具体前缀可能叠加。分别查新会话选路、老会话固定出口与回程，不靠一张当前路由表解释历史会话。

## 3. 证据

收集新建失败、端口/会话资源、分配失败、超时和结束原因，关联具体五元组。只看到全局会话数很高不能证明已耗尽；只看平均CPU低不能排除单核/映射池瓶颈。

## 4. 修复与实验

优化应用连接复用、合理超时、映射池与架构，先明确作用机制。缩短UDP超时可能破坏空闲业务，加公网IP也不解决所有状态同步问题。用隔离目标测试短连接/长连接、故障与恢复，不对第三方服务压测。
