# 规则生命周期、日志与策略排障

[返回本部分学习目录](../Network-Security-and-Access.md)

## 1. 从申请到退役

规则包含业务负责人、用途、源/目的、服务、身份、有效期、日志与变更号。上线后复查命中与访问范围，临时例外到期撤销。零命中不能直接删除，可能仅在季末、灾备或维护时使用，需业务确认和观察窗口。

## 2. 排错顺序

先确认请求真实发出与目标解析，再查路由、区/接口、NAT、命中和状态，最后看目标与回程。某产品日志显示规则未命中，可能包还没走到检查点，不是规则错；日志缺失也可能未启用、聚合或采集延迟。

| 症状 | 区分证据 |
|---|---|
| 无会话 | 包到没到、路由/区/过滤早期处理 |
| 单向计数 | 目标响应、返回路由/NAT和不对称 |
| 策略允许仍失败 | TLS/身份/后端服务及深度检查 |
| 新规则无效果 | 顺序/对象、发布范围和旧会话缓存 |
| 仅大包失败 | MTU、分片、隧道与错误反馈 |

## 3. 内容检查的边界

IPS、恶意内容、URL、DNS过滤与TLS解密各有作用、性能及兼容影响。组织决定解密范围、信任发放和隐私要求；不能通过关闭客户端证书校验“解决”拦截错误。例外需精确、到期且可审计。

## 4. 性能与维护

转发、加密、完整安全检查、日志和小包pps有不同能力上限。升级后确认签名、规则解析、会话和应用识别，单看设备CPU平均值不够。

## 5. RCA练习

案例为规则放行但登录失败，候选TLS检查不兼容、应用授权拒绝和回程丢失。给出会话、证书、响应码与目标抓包等区分证据，单变量修复并验证无关拒绝规则仍有效。
