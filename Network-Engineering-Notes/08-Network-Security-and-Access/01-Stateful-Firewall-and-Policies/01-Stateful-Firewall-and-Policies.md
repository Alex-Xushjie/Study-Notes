# 有状态防火墙、会话与策略

[返回本部分学习目录](../Network-Security-and-Access.md)

## 1. 区分路由、策略和状态

路由决定下一跳，安全策略判断是否允许，状态表记录连接/流的处理上下文。某产品查路由、NAT、安全和应用识别的具体顺序依平台而异，不能把一个厂商包流程当通用标准。

TCP状态、UDP超时与ICMP关联处理不同。UDP没有TCP握手，但有状态防火墙仍可能为UDP维护映射和超时。已有会话还可能缓存策略/出口，修改规则后要区分新旧会话。

| 对象 | 应记录 |
|---|---|
| 原始流 | 源/目的、端口、协议、入接口/区、VRF |
| 规则 | 命中ID、方向、服务/应用/身份与默认动作 |
| 状态 | 创建时间、双向计数、超时与结束原因 |
| 路径 | 下一跳、出口、NAT前后地址 |
| 应用 | TLS/HTTP/数据库等实际结果 |

## 2. 最小权限规则

访问需求写为“谁从哪里访问哪项服务，目的和期限是什么”，再转换地址、身份、服务/应用条件。允许TCP443不等于只允许一个SaaS，应用识别也不天然覆盖所有加密/新协议。

分区需考虑管理、用户、服务器、访客、OT辅助和外部合作方。公网防护与内部分段职责不同，内网流量也不能默认可信。

## 3. 规则验证

规则顺序、对象组、Negate/Any、默认行为、日志与命中均需核对。计数增长不证明目标请求命中，可能是同规则其他流量。采用新测试会话和限定五元组，对照两端证据。

## 4. 练习

设计App→DB TCP5432允许、其他跨区拒绝，分别验证正常、返回、旧会话和不匹配端口。拒绝必须来自策略而非DNS错误。保留原值与回退，不全局清状态表测试。

[防火墙策略指导NIST SP800-41r1](https://csrc.nist.gov/pubs/sp/800/41/r1/final)。它提供设计原则，不替代现代产品具体包流程与支持矩阵。
