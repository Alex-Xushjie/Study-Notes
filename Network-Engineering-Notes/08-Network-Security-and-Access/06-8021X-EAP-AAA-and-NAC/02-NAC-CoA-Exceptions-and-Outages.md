# NAC、CoA、例外设备与AAA故障

[返回本部分学习目录](../Network-Security-and-Access.md)

## 1. NAC超出一次认证

NAC可结合身份、设备分类、姿态、位置与策略决定访问，但分类推断不是不可伪造身份。MAB以MAC相关信息作为兼容认证路径，不能等同证书；打印机/IoT例外应有最小权限、负责人和退役时间。

## 2. 动态授权

CoA/Disconnect用于改变或终结相应会话，需正确NAS/会话标识、授权与传输保护。收到请求不一定表示设备已成功应用新角色，核对ACK/NAK、接入口状态和业务。

| 场景 | 注意 |
|---|---|
| 重新认证 | 是否换VLAN/地址、旧连接如何处理 |
| 共享端口 | 电话+PC、AP或下挂设备的会话模式 |
| 用户/机器认证 | 不同阶段身份与授权变化 |
| MAB回退 | 不允许强身份失败自动获得过宽权限 |
| AAA故障 | 已有、新接入、重认证与恢复分别定义 |

## 3. Fail-open/close

AAA不可用时可能阻断或进入限制性Critical角色，取决于组织业务和风险。不能把服务器明确拒绝与服务器不可达混成同一触发，也不能为保持“不断网”默认给全部员工权限。

## 4. 实验矩阵

测试正确认证、明确拒绝、服务器超时、证书续期、CoA、终端换端口和服务器恢复。记录身份、端口、角色、IP与许可。批量上线/重认证会给AAA与DHCP带来峰值，评估故障恢复风暴。

## 5. 交付

输出角色/访问矩阵、例外清单、AAA冗余与状态变更流程。结合园区端口和无线转发实际验证，不能只凭AAA平台日志宣布接入隔离合格。
