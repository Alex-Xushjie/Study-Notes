# ZTNA、SSE、SASE与资源级接入

[返回本部分学习目录](../Network-Security-and-Access.md)

## 1. 目标与产品标签分开

零信任架构强调基于身份、设备、资源和上下文的访问判断，不因位于内网而默认信任。ZTNA通常提供资源/应用级接入，SSE聚焦云交付安全能力，SASE结合连接与安全；具体功能、代理模式和授权因产品而异。

ZTNA不保证任意IP协议、组播、旧客户端或站点Transit都支持。传统VPN仍可能承担特定网络需求，替代应按应用清单与证据，不按口号一刀切。

## 2. 决策与执行

策略决策点判断，执行点控制会话，连接器/代理/安全PoP可能在数据路径上。管理门户在线不等于连接器可达，身份通过不等于应用授权或后端健康。

| 依赖 | 可能影响 |
|---|---|
| IdP/MFA | 新登录与刷新 |
| 设备姿态 | 角色和访问条件 |
| Connector | 私有服务可达与容量 |
| DNS/TLS | 应用匹配、名称与证书 |
| PoP/骨干 | 数据路径、时延和故障域 |

## 3. 分段与失败模式

把用户到资源的允许矩阵落实，避免某连接器实际开放整个网段。Connector的出站/入站、权限与高可用按产品核对。PoP失败时换点、回总部、绕过或阻断需逐业务定义并获组织认可。

## 4. 练习

选Web、SSH、数据库、UDP实时业务四类，逐项核对协议、终端、身份、路径、日志和失败恢复。对不支持项保留替代设计，不把代理演示成功泛化全部VPN替代。
