# 接入迁移、安全服务链与验收

[返回本部分学习目录](../Network-Security-and-Access.md)

## 1. 先清点应用

应用域名/地址、端口、协议、身份、客户端、依赖、长连接和供应商维护逐项登记。迁移前确认DNS、证书、源地址白名单、日志和访问路径如何变化；不能只检查主页能打开。

## 2. 灰度并行

先选择测试用户/应用，再扩大。旧VPN与新代理并存可能发生路由/DNS竞争、双代理检查或身份策略冲突，记录哪套系统负责哪个资源。客户端卸载/升级也需回退和支持流程。

## 3. 双向与源身份

代理终结连接后，后端看到的地址可能变为Connector/PoP。网络日志与应用身份需可靠关联，不能用不可信首部直接认人。检查后端许可是否误放宽到所有连接器访问全部资源。

## 4. 验收矩阵

| 条件 | 测试 |
|---|---|
| 正常 | 真实登录、核心事务、长会话 |
| 拒绝 | 错用户/设备/角色和非授权资源 |
| 故障 | IdP、Connector、PoP、DNS分别失败 |
| 撤权 | 账号/设备禁用、Token过期与活动会话 |
| 回退 | 客户端/路径恢复和无遗留暴露 |

业务成功率、响应分位数与容量要对照旧路径，不能只看安全门户绿色。Fail-open/close是业务和安全共同决定，不让缺省值代替设计。

## 5. 交付

应用兼容矩阵、路径与身份链、灰度/回退、日志关联及未支持清单。设备或云环境未实测的能力标待验证，不在作品集中写“已完成全企业零信任改造”。
