# HA倒换、升级与会话验收

[返回本部分学习目录](../Network-Security-and-Access.md)

## 1. 四种恢复结果

已有TCP继续、新TCP成功、UDP流恢复、VPN/身份会话恢复分别测试。有的方案保留转发状态，却使TLS代理或远程用户重连；一次ping不中断不能证明全部无损。

## 2. 测量时间线

t0注入，t1检测，t2角色/路径变化，t3新会话成功，t4原业务恢复。跨机时间需同步并说明精度。只测t2会漏掉应用重试与认证时间。

| 测试流 | 观察 |
|---|---|
| 长TCP传输 | 重传、重置、连续性与完成时间 |
| 短HTTPS事务 | 成功率、延迟与出口IP |
| UDP实时流 | 序号gap、乱序和连续间断 |
| VPN用户 | 隧道、身份、地址/DNS和授权 |
| 管理/日志 | 值班入口与审计是否仍可用 |

## 3. 升级

核对双机兼容、升级顺序、配置转换、授权与回滚限制。所谓滚动升级不一定保持所有会话；升级期间可能失去冗余。先实验并按业务窗口分批，保留原配置、镜像与恢复路径。

## 4. 恢复切回

抢占、状态重同步、连接排空和路由回迁可能再次中断。明确自动/人工切回条件，避免链路抖动不断触发角色变化。恢复后确认同步真正稳定与临时配置已撤。

## 5. 练习

交付故障矩阵、各流的预期/实测、N-1资源与残余风险。若仅虚拟双机逻辑模拟，不能证明硬件电源、板卡和物理网络故障域。
