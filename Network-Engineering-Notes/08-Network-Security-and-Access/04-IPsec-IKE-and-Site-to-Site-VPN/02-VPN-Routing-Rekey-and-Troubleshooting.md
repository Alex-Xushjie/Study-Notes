# 站点VPN路由、Rekey与排障

[返回本部分学习目录](../Network-Security-and-Access.md)

## 1. Route-based与Policy-based

Route-based常通过逻辑隧道接口和路由引流，Policy-based依据相应流量选择器/策略保护业务，但具体实现可能仍有Selector约束。两端必须协商一致的业务范围，NAT顺序和平台行为也要核对。

## 2. 逐层定位

从源端确认S/D/端口、路由和应用，检查本端封装前计数、加密发出、对端解密、内网出口、目标响应和返回封装。若本端加密增长而对端不解密，不能立即认定线路丢包，还需SA匹配、认证/重放丢弃与实际出口证据。

| 现象 | 首查 |
|---|---|
| 只有一个子网不通 | Selector、路由、NAT与策略范围 |
| 小包通大包卡 | 内层MTU、封装与PMTUD |
| 固定周期断 | SA生命周期、Rekey与映射 |
| 主备线路切换失败 | 外层地址、身份、状态与路由 |
| 业务断而DPD正常 | 探测目标不代表应用路径 |

## 3. 密钥更新

Rekey是正常生命周期的一部分，需验证双端时间参数、并发协商、旧新SA交替与故障恢复。只测初次建隧道会漏掉长时间问题。证书轮换需包含中间链、信任分发与过期前告警。

## 4. 实验

在两隔离设备间先单子网低速业务，再增加第二子网、双向、较大报文和长连接；覆盖一次Rekey、主路径失效及恢复。故意错一个Selector或NAT条件，解释两端各看到什么。
