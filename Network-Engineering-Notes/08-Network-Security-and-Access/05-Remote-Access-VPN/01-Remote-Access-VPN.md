# 远程接入VPN、地址、DNS与授权

[返回本部分学习目录](../Network-Security-and-Access.md)

## 1. 用户登录只是一步

远程用户需要正确客户端/设备状态、网关发现、证书与身份、MFA、隧道、地址/路由、DNS及资源授权。用户显示Connected并不说明内网服务可用；能访问一个网站也不代表所有私有资源权限正确。

Full Tunnel把指定范围流量送到企业路径，Split Tunnel按定义目标分流，具体还涉及IPv6、DNS与平台排除规则。分流策略同时影响安全、隐私、容量和SaaS入口，需要组织决策，不默认一方始终更好。

| 层次 | 要确认 |
|---|---|
| 身份 | 用户/设备、MFA、组与会话期限 |
| 隧道 | 协议、代理/UDP回退、断线重连 |
| 地址 | 客户端地址池不与家庭/DC/云重叠 |
| 路由 | 内网/默认/IPv6、是否冲突或泄漏 |
| DNS | 分流后缀、服务器可达与浏览器解析 |
| 授权 | 只能访问需要的应用/区，不是整网开放 |

## 2. 地址重叠

家庭网与公司同为192.168.1.0/24时，客户端可能优先本地路径或发生歧义。不能用“隧道已通”跳过。地址规划、受控NAT、应用代理或重编号按实际需求选择，记录DNS和日志影响。

## 3. 客户端与网关

客户端版本、操作系统、证书存储、EDR/防火墙和网络代理均影响行为。记录实际选择的传输，不把TLS/TCP回退与UDP数据面性能当相同。TLS VPN产品名称并不保证实现和版本支持一致。

## 4. 练习

按一个合法实验用户完成登录→地址→路由→私有DNS→TCP/TLS→业务授权，保存脱敏证据。测试错误角色、过期身份和资源拒绝，禁止以给用户管理员权限修复接入。

[零信任架构](https://csrc.nist.gov/pubs/sp/800/207/final)、[TLS1.3 RFC8446](https://www.rfc-editor.org/rfc/rfc8446.html)。具体远程协议与功能以目标产品为准。
