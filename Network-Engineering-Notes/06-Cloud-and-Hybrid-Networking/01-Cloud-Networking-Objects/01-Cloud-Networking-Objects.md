# 云网络对象与传统网络思维转换

[返回云与混合网络目录](../Cloud-and-Hybrid-Networking.md)

## 1. 先理解控制边界

云网络仍然处理地址、路由、过滤与状态，但用户通常配置逻辑对象，由平台实现分布式转发。VPC/VNet不是一台你能登录的核心交换机，子网也不应按传统广播域的全部行为推断。ARP、广播、组播、镜像和路由协议支持要按服务核对。

| 对象 | 网络工程师应理解的含义 | 不能直接类比 |
|---|---|---|
| 账户/订阅、项目 | 资源归属、授权、配额与费用边界 | 不等于天然的数据面隔离策略 |
| VPC/VNet | 地址与逻辑网络边界 | 不是所有平台都具有相同区域范围 |
| 子网 | 地址分配及关联策略的范围 | 不必对应传统交换机的一切二层能力 |
| ENI/NIC | 工作负载的逻辑网卡与地址/策略关联 | 不代表可任意桥接或开启混杂模式 |
| 路由表 | 平台定义的下一跳与路径规则 | 不是完整支持所有CLI的传统RIB |
| 网关/端点 | 特定连接或服务访问功能 | 名称相似不表示能力相同 |

AWS VPC是区域级，子网属于一个AZ；Azure VNet是区域级，子网不绑定单一AZ。Google Cloud VPC具有全局范围、子网是区域级。这些差异影响地址、容灾与资源组织，不能拿同一张模板直接套用。

## 2. 控制面与实际流量

API创建成功表示对象被接受，不证明路由安装、权限、DNS、服务监听及应用全部正确。一个工作负载还依赖网卡、安全策略、身份、系统防火墙和应用。平台有效路由、流日志、路径分析与真实请求需结合。

托管服务隐藏了部分底层细节，同时提供新的可观测对象。排障时将资源ID、区域/AZ、网卡、路由关联与时间窗记录下来，不能只写“云上服务器”。

## 3. 责任与权限

云厂商维护基础设施，不替企业决定地址规划、路由互通、访问授权和应用安全。网络可达与IAM授权是两条不同判断链；HTTP 403可能表示请求已到服务却被权限拒绝，不应立即修改路由。

学习CLI时优先只读查询，固定账号/订阅、区域和资源ID。生产资源即使名字包含test，也不能据此当成实验环境。自动化还要保留配置所有权与变更审计。

## 4. 学习检查

画“组织—账号/订阅—区域—逻辑网—子网—网卡—进程”的资源树，并另画业务包路径。解释为什么VPC连接已建立仍不能收HTTP，为什么两云都叫Subnet但容灾边界不同。
