# 逐跳流量模型与设计输入

[返回云与混合网络目录](../Cloud-and-Hybrid-Networking.md)

## 1. 一条请求至少查六项

以本地客户端访问云内ERP为例：客户端先解析域名，按本地路由进入WAN；云边界接收报文，经云侧路由与安全检查到工作负载；应用处理后按返回路径回应。专线或VPN只覆盖其中一段。

固定源地址、源位置、目的域名、解析结果、端口、协议、VRF与时间。再记录NAT前后地址、各路由表、状态设备与服务身份。请求返回也要完整画出，不能用一根双向箭头代替两个方向的决定。

| 层次 | 需要的证据 |
|---|---|
| DNS | 谁回答、CNAME链、最终地址、私有区可见性 |
| 本地/WAN | 业务前缀、端点路由、主备偏好与MTU |
| 云接入/Transit | Attachment/Connection、入口查哪张表 |
| 工作负载子网 | 路由关联、下一跳、有效路由 |
| 安全 | 平台规则、检查链、系统防火墙、身份 |
| 应用 | 监听、TLS、响应码、后端依赖与健康 |

## 2. 设计输入清单

先收集组织边界、区域、业务等级、地址与增长、既有重叠、站点互访、安全检查、DNS、私有服务、吞吐/pps、容灾目标和运维权限。没有这些，选择TGW、Virtual WAN或NVA只是在挑产品。

恢复目标需区分网络恢复、应用恢复、RTO和数据RPO。网络双路可达不保证数据库已同步，也不保证业务自动切区。容量表至少含正常、单AZ/单链路与区域级失败。

## 3. 四张交付图

资源与归属图说明账号/订阅、区域及负责人；路由图说明前缀和查表顺序；安全与DNS图说明访问链和解析方向；故障域图说明共享线路、网关、区域、身份和管理依赖。

图中用实线标已有、虚线标设计，不把计划中的备用连接写成现网能力。所有资源带可追踪标识，教材例子只用实验私网和保留域名。

## 4. 桌面推导

给定DC 10.100.0.0/16、Prod 10.10.0.0/16、Shared 10.30.0.0/16，推导DC→Prod HTTPS与Prod→Shared DNS。再删除Shared的返回路由，观察为什么正向路由完整仍失败。将一次权限拒绝与网络超时分开定位。

## 5. 验收方式

每条允许与拒绝流各有预期、配置证据和实际请求。可达不证明隔离正确，拒绝也可能只是DNS坏了。测试拒绝时确认请求发向正确目标并有相应拒绝证据。
