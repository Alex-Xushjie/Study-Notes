# 四类云网络故障与RCA

[返回云与混合网络目录](../Cloud-and-Hybrid-Networking.md)

## 1. 案例一：BGP正常，本地访问云超时

假设A为云业务子网缺回程，B为SG/NSG拒绝，C为服务未监听。先确认本地实际目标与路由，再在云端观察SYN是否到达、是否响应，并查子网有效路径和流日志。BGP会话只覆盖边界控制连接，不排除A/B/C。

若云端收到SYN并发出SYN-ACK，本地未收到，则沿回程定位；若主机收到但不回应，查系统与监听。不要只扩大平台安全规则。

## 2. 案例二：云内可访问私有服务，本地失败

先比较DNS答案和CNAME链。若本地解析公网，检查条件转发/私有区可见性；若均为私网，查混合路由与端点规则；若TLS成功后返回拒绝，检查资源权限和端点策略。

用保留主机名的指定解析测试区分DNS与业务路径。临时hosts改善只能支持解析问题假设，永久修复仍应回到DNS设计。

## 3. 案例三：平均带宽低，出站连接间歇失败

候选为SNAT端口/映射压力、DNS瓶颈、远端限流或应用连接池。收集并发与目的分布、NAT错误、DNS延迟、HTTP状态和重试。降低连接创建率或启用正确连接复用后改善，需在相同负载下验证，不因平均带宽低就排除网关资源。

## 4. 案例四：插入防火墙后单向通信

核对App与Data双向有效路由、检查设备会话、NAT与转发。可能一方向走检查、另一方向走直达路径，也可能目的监听故障。对同一五元组采集两个方向，不能用全局计数证明具体流量经过。

## 5. Linux端点观察

eth0与地址为占位；ss显示Socket，ip显示系统路由，tcpdump用于有限抓包。主机ip route不会展示全部云平台分布式路由，需要与云控制面结果对照。

~~~bash
ip -br addr
ip route get 10.20.0.10
ss -lnt
ss -t -a -n -i
sudo tcpdump -ni eth0 -c 100 'host 10.20.0.10 and tcp port 8000'
~~~

## 6. RCA交付

列影响、时间线、事实、候选、区分实验、根因、临时恢复、永久修复、回归和未确认项。至少保留一项反证，说明为何不是另一个候选。恢复路由、撤临时规则和更新IaC/台账都属于完成条件。
