# 网络费用、配额与架构取舍

[返回云与混合网络目录](../Cloud-and-Hybrid-Networking.md)

## 1. 按完整流量链计算

网络费用可能来自网关/端点时长、数据处理、跨AZ/区域、互联网出口、专线、日志、LB与安全服务。某些费用可叠加，是否豁免取决于服务、路径与区域。不要只比较一项每GB单价就决定架构。

| 成本项 | 建模信息 |
|---|---|
| 固定运行 | 实例/网关/端点数量、AZ覆盖、小时数 |
| 数据处理 | 实际经过哪些计费对象、各方向是否计量 |
| 传输 | 同区/跨AZ/跨区/公网、发出与接收方规则 |
| 观测 | 日志生成、写入、存储、查询和保留 |
| 运营 | 授权、管理、工单、恢复复杂度与人力 |

## 2. 假设价格例子

纯教学设定：某网关0.05货币单位/小时、处理0.04/GB，730小时、1000GB，一个网关估算36.5+40=76.5。这里不是任何云产品报价，未含税、传输、日志与其他服务。真实预算按目标区域当前官方价格计算。

集中出口可能减少网关数量，却增加跨AZ/区与Transit处理；分布式端点可能增固定时长费用，却改变数据路径。对比时统一可用性、流量方向和安全目标，避免拿单AZ低成本方案对比跨AZ高可用方案。

## 3. 配额和资源规模

路由数量、Attachment、Peering、端点、DNS查询、网卡IP、规则、BGP前缀和NAT并发都可能有限制。区分可申请配额与硬限制，提前评估申请周期和区域支持。

容量规划还包括新建突发与恢复风暴：大规模实例启动同时解析DNS、拉镜像、建立连接，平稳日均不能代表峰值。单条隧道/单流与汇总吞吐也不同。

## 4. 成本优化顺序

先找实际流向和计费归属，再检查无用资源、绕行、日志保留和可替代服务。减少冗余或绕过检查可能损害恢复与安全，不应仅按账单数字推动。对优化前后业务质量与故障能力做相同验收。

## 5. 练习

比较集中NAT/安全出口、各AZ本地出口、私有端点三种路径，列固定/流量/观测费用与故障域。无需真实开资源，也能交付带假设、公式和官方计价入口的模型。
