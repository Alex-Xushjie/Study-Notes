# AZ、区域与混合接入故障域

[返回云与混合网络目录](../Cloud-and-Hybrid-Networking.md)

## 1. 故障域是依赖集合

两台VM不等于跨AZ；跨AZ不等于跨区域；跨区域也可能共用本地CE、云接入位置、DNS或身份服务。区域性托管服务是否内部多AZ与客户端配置要求按服务核对，不凭资源图标位置推断。

| 失败对象 | 可能的保护 | 仍需验证 |
|---|---|---|
| 单VM/NVA | 健康检查、备用实例、状态策略 | 转发能力与旧会话 |
| 单AZ | 工作负载与网络路径跨AZ | NAT/端点/检查资源的区域或AZ模型 |
| 单接入位置 | 多位置与客户/运营商多样性 | 实际物理路径、路由与容量 |
| 单区域 | 第二区域业务与网络依赖 | 数据、DNS、身份、授权和人工切换 |
| 集中管理失效 | 缓存状态/灾备控制 | 新变更、恢复、长时依赖 |

## 2. 可用率不能随意相乘

教学独立模型中，两条各99.9%可用的路径并联，理论同时不可用率为0.001²，可用率99.9999%。独立、切换成功、容量足够等假设在现网未必成立；共管道或同电源会使估算失效。

串联依赖越多，整体可用受影响。产品SLA、应用SLO和实际故障预算不是同一件事，必须写清测量边界与排除项。

## 3. 多区域路由

跨区域可能使用Peering、Transit互联或广域骨干服务，路由传播/传递能力各异。工作负载复制、服务发布和DNS切换还要协调，不能只把跨区网络连通叫业务容灾。

双活需明确源数据、写入模型、流量入口和状态；主备需定义触发、人工介入、回切及数据一致性。网络工程师负责网络证据，同时与应用/数据库团队确认恢复条件。
