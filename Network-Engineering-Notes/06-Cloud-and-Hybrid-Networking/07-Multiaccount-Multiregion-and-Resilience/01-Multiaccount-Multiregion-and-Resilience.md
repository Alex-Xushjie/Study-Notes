# 多账号、订阅与网络治理

[返回云与混合网络目录](../Cloud-and-Hybrid-Networking.md)

## 1. 管理边界和流量边界分开

多账号/订阅可划分团队、环境、权限和费用，但不会自动实现所需网络连接，也不自动构成所有层面的安全隔离。Prod与Dev如何互通取决于路由、规则、身份和共享服务，不能只看组织树。

集中网络团队可维护地址、Transit、DNS和出口，业务团队管理工作负载与应用策略。分工需要明确谁能创建连接、传播路由、修改规则、发布DNS、审批端点和查看日志。

## 2. 共享对象的风险

AWS资源共享、跨账号私有区/规则关联，Azure跨订阅连接/链接，都依赖具体支持和权限。共享一个TGW/Hub不表示所有网都互通；共享DNS规则也不表示所有VPC/VNet都已正确关联。

| 对象 | 所有者职责 | 使用方职责 |
|---|---|---|
| IPAM/地址池 | 分配与冲突检测 | 按流程申请，退役归还 |
| Transit/Hub | 路由表、隔离和连接审计 | 子网路由、业务前缀与回程 |
| DNS | 权威、转发、可用性 | 记录、应用缓存与依赖 |
| 出口/安全 | 检查、容量、策略与日志 | 精确访问需求与测试 |
| 预算/配额 | 告警、容量与增长 | 使用归属与异常解释 |

## 3. 配置即代码与漂移

IaC可记录网络意图和审查差异，但Plan成功不证明业务可用。把路由关联、传播、DNS链接、安全与日志纳入相同变更包；保留依赖顺序与回退。控制台临时修复应回写受控配置，否则下次自动部署可能覆盖。

不用教材主动运行apply/destroy。真实变更按组织授权与流水线执行。仓库不存长期云密钥、私钥、生产令牌或敏感拓扑导出。

## 4. 护栏与例外

设置创建区域、地址、标签、日志、公开暴露和连接审批等护栏。例外需要明确范围、负责人、到期和复核，避免一个临时0/0路由或公网入口长期存在。

## 5. 练习

给网络团队、Prod、Dev、审计四角色写权限与操作矩阵，再模拟业务方申请新VPC/VNet接入。提交从地址申请、连接、DNS、路由到允许/拒绝测试的完整流程。
