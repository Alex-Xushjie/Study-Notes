# 混合云IPAM、地址重叠与分段

[返回云与混合网络目录](../Cloud-and-Hybrid-Networking.md)

## 1. IPAM是可运营的分配流程

IPAM不仅记录网段，还记录归属、环境、区域、用途、负责人、分配状态、汇总边界与退役时间。多账号/订阅自行选择10.0.0.0/16，早期互不连接时看似无碍，后期专线/Transit互联会暴露重叠。

| 分配层 | 示例信息 | 设计目标 |
|---|---|---|
| 企业地址池 | DC/云/分支/合作方 | 避免全域重叠 |
| 区域/环境块 | Region-A Prod/Dev/Shared | 可汇总且可分段 |
| 网络 | VPC/VNet CIDR | 增长和连接范围明确 |
| 子网 | 业务、网关、端点、检查 | 满足服务尺寸与专用要求 |
| 特殊池 | VPN客户端、容器、隧道、NAT | 避免隐藏冲突 |

保留地址、最小/最大子网、托管服务专用子网与扩展限制因平台不同，计算可用地址前查对应规则。不要把传统减2公式套到所有云子网。

## 2. 重叠不是路由优先级问题

两侧都用10.10.0.0/16时，本地路由可能吸收目标，Peering或Transit也可能拒绝/限制传播。提高BGP偏好不能让同一个地址同时唯一定位两台不同主机。

方案包括重编号、专门NAT、应用代理、服务级私有发布或保持隔离。每个方案有DNS、日志、白名单、应用内嵌IP和运维代价。明确转换前后地址与双向路径，不用“加一层NAT”一句话结束设计。

## 3. 分段矩阵

Prod/Dev隔离，均可访问Shared与DC，是路由与安全的联合设计。共享服务主机若可任意代理转发，也可能成为绕过隔离的通道。矩阵应列源区、目标服务、协议、身份及检查点。

能源企业可分办公、生产辅助、视频、管理等，但具体生产控制分区/云接入必须经过相应业务与安全评审。本教材给通用隔离方法，不为任何控制系统承诺合规承载。

## 4. 演练

为DC、两云、两区域、Prod/Dev/Shared建立不重叠规划，预留增长与容器地址。加入一个地址重叠的并购站点，比较重编号与服务代理/NAT，说明为什么某些协议不能透明迁移。

[AWS IPAM](https://docs.aws.amazon.com/vpc/latest/ipam/what-it-is-ipam.html)。具体工具可不同，统一分配与审计责任不能省略。
