# 出站设计、SNAT与IPv6

[返回云与混合网络目录](../Cloud-and-Hybrid-Networking.md)

## 1. 本地出口与集中出口

分布式出口减少部分绕行与跨区依赖，但需管理更多公网IP与安全策略；集中出口便于检查与白名单，却增加Hub、跨区流量与状态故障域。选择依据是业务、安全、成本和恢复目标，不是统一追求所有流量回总部。

NAT把源地址/端口转换为出口映射，不等于应用代理或访问控制。互联网主动入站需要明确发布机制，不能因有SNAT就认为外界可以连接后端。

## 2. 端口与连接容量

大量客户端访问同一个远端地址/端口时，SNAT映射可能成为瓶颈，即使带宽低。配额、分配方式、空闲超时、并发和扩容方法随产品不同，不给所有NAT套一个“固定64000连接”结论。

教学简化：请求每秒2000次、每次占用映射30秒，稳态同时占用量约60000；真实HTTP连接复用、TIME_WAIT、NAT超时和多目的分布会改变结果。这是容量直觉，不是产品上限。

## 3. 出口变化影响业务

NAT/线路切换可能改变源公网IP，使第三方白名单、条件访问和会话状态失效。记录SNAT前后地址、出口资源、日志与服务方限制。连接恢复与原会话延续分别测试。

## 4. IPv6

IPv6工作负载可以有可路由地址，安全边界不能继续靠“没有IPv4公网映射”解释。按地址族定义路由、过滤与出站机制；需要IPv6-only访问IPv4服务时，还涉及适用的DNS64/NAT64等能力，不是IPv4 NAT Gateway配置自动覆盖。

应用的双栈选择可能掩盖一栈故障。分别记录A/AAAA结果与实际连接地址。不要只验证IPv4就发布“出口正常”的监控结论。

## 5. 验收

覆盖并发短连接、长连接、空闲后重连、故障切换、IPv4/IPv6及第三方白名单。查看映射/端口、丢弃、连接失败与应用成功率，平均吞吐不能排除端口耗尽。

[AWS NAT Gateway行为](https://docs.aws.amazon.com/vpc/latest/userguide/nat-gateway-basics.html)、[Azure NAT Gateway资源](https://learn.microsoft.com/en-us/azure/nat-gateway/nat-gateway-resource)。部署前核对产品当前SKU/可用区模型，不把区域级与分区级实现混为一谈。
