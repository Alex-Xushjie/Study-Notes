# 网卡、地址与普通路由：先读懂一台Linux主机

[Linux学习目录](../Linux-Networking.md) · [前置：Linux入门](../01-Linux-Essentials/01-Linux-Essentials.md)

## 1. 本篇只解决最先遇到的三个问题

Linux把网卡叫作什么？在哪里看IP地址？在哪里看它到外部网络的路由？你已经知道地址和网关的含义，这里学习的是Linux如何表达这些信息。

先使用只有一个普通业务/实验网卡的模型，读懂输出之后再进入多表、策略路由和VRF。所有输出均为教学示例，不是本次实测，也不要求你的机器显示相同名称与地址。

## 2. ens160是什么：它是接口名称

在交换机上你会看到GigabitEthernet或Ethernet一类端口名，Linux也要为网络接口命名。ens160只是可能出现的一个名字，不是命令，也不是Linux组件名称。

先在Linux终端输入：

~~~bash
ip -br link show
~~~

示例：

~~~text
lo               UNKNOWN        00:00:00:00:00:00 <LOOPBACK,UP,LOWER_UP>
ens160           UP             00:0c:29:12:34:56 <BROADCAST,MULTICAST,UP,LOWER_UP>
~~~

第一列是接口名，第二列是运行状态，后面还可以有链路地址和标志。lo是loopback回环接口，供本机内部通信使用；ens160在本例中是虚拟机的一块以太网接口。它不一定是你机器的名字。

| 可能看到的名字 | 常见含义 | 第一遍怎么处理 |
|---|---|---|
| lo | 本机回环接口 | 认识即可，不当作插网线的口 |
| eth0 | 常见传统以太网命名 | 可能是当前实验网卡 |
| ens160、ens33 | 常见基于设备信息生成的名字 | 以实际输出为准 |
| enp0s3、enp1s0 | 常见基于设备路径信息的名字 | 不必现在背编号规则 |
| wlp2s0等 | 可能是无线接口名 | 先确认设备类型 |
| bond0、br0 | 常见逻辑接口自定义名 | 后续专题解释 |

许多systemd系统的命名方案用en表示Ethernet，用wl表示无线；后续字符与固件/设备路径等信息有关。但系统可自定义名称，ens160不代表第160个前面板端口，更不代表网速或用途。[接口命名方案](https://www.freedesktop.org/software/systemd/man/latest/systemd.net-naming-scheme.html)

后面的例子写ens160时，你应代入自己查到的接口名。若系统只有enp0s3，直接查询ens160会提示设备不存在，不是网卡坏了。

## 3. 逐个拆开ip命令

ip是Linux中常用的网络管理工具，通常来自iproute2软件包。同一个工具通过不同对象查看接口、地址、路由等。[ip命令语法](https://man7.org/linux/man-pages/man8/ip.8.html)

| 写法 | 对象或动作 | 含义 |
|---|---|---|
| ip link show | link是接口/链路对象 | 查看接口 |
| ip address show | address是地址对象 | 查看接口地址 |
| ip route show | route是路由对象 | 查看普通路由 |
| ip neigh show | neigh是neighbor的缩写 | 查看邻居信息，IPv4常对应ARP关系 |
| -br | brief，显示选项 | 简短显示 |
| -4 | IPv4，协议族选项 | 限定IPv4信息 |
| dev ens160 | 指定设备参数 | 只针对名为ens160的接口 |

ip address也常缩写为ip addr。刚开始阅读时使用完整写法，避免把缩写误认成另一个工具。此阶段的show表示查看，后续的add、delete、set才可能改变状态。

## 4. 在哪里看本机IP地址

~~~bash
ip -br address show
~~~

示例：

~~~text
lo               UNKNOWN        127.0.0.1/8 ::1/128
ens160           UP             10.10.10.10/24
~~~

第一列仍是接口名，最后列出地址。ens160上配置10.10.10.10/24；lo上有本机回环地址127.0.0.1和IPv6的::1。你已经知道/24含义，这里不用重新计算子网。

如果只想看这块接口的IPv4地址，可以输入：

~~~bash
ip -4 address show dev ens160
~~~

输出可能更详细：

~~~text
2: ens160: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 state UP
    link/ether 00:0c:29:12:34:56 brd ff:ff:ff:ff:ff:ff
    inet 10.10.10.10/24 brd 10.10.10.255 scope global ens160
~~~

2是接口索引，不是VLAN号。link/ether这一行给出以太网链路地址信息；inet表示IPv4地址信息；brd表示broadcast广播地址；mtu是接口MTU。scope global不表示一定是公网地址，示例私网地址也可这样显示。

第一遍先找接口名、状态、inet地址与MTU，暂时不用把每个输出字段都背下来。

## 5. UP到底表示什么

Linux区分管理上启用与下层/运行状态。详细输出的UP标志通常表示管理员允许使用接口，LOWER_UP表示驱动等报告下层就绪；简表中的状态不能与所有标志混为一谈。

如果一个以太网接口有UP标志却NO-CARRIER，先检查物理连接、交换机口或虚拟机虚拟网卡连接。lo出现UNKNOWN并不自动代表故障，虚拟接口与物理口的运行状态含义要结合类型。[内核运行状态说明](https://docs.kernel.org/networking/operstates.html)

你熟悉的判断仍适用：接口就绪不能证明网关、路由、安全策略、服务和回程都正确。这里先学看懂状态，后续再拆复杂逻辑接口。

## 6. 在哪里看路由：先认识普通情况

~~~bash
ip -4 route show
~~~

假设这台主机使用10.10.10.1作为网关，输出可能是：

~~~text
default via 10.10.10.1 dev ens160
10.10.10.0/24 dev ens160 proto kernel scope link src 10.10.10.10
~~~

先读第一行：“默认目的通过10.10.10.1，使用ens160接口。”再读第二行：“10.10.10.0/24从ens160直接交付，此路由记录首选源地址10.10.10.10。”

| 字段 | 含义 | 对应已有网络知识 |
|---|---|---|
| default | 默认路由，此处为IPv4的0.0.0.0/0 | 兜底目的前缀 |
| via | 经由的下一跳 | 网关地址 |
| dev | 使用的设备/接口 | 出接口 |
| proto kernel | 该条路由标记为内核来源 | 常见于内核生成的前缀路由；不是业务包协议 |
| scope link | 这条路由描述链路范围可交付目标 | 本例的直连前缀 |
| src | 该条路由的首选源地址信息 | 不等于把所有业务源地址强制改写 |

路由不带via不一定异常，直连交付本来就不必指定另一个网关。此处default是路由条目，不是网卡，也不是一个程序。

### main又是什么

Linux可以保存多张路由表。main是其中一张普通路由表的名称，表号是254。把它先理解为“装有常用普通路由的一本表”，而不要把main理解为主网卡或主进程。

默认不指定表时，下面两条通常展示同一张表：

~~~bash
ip -4 route show
ip -4 route show table main
~~~

table表示“指定哪张表”，main是这里的表名。普通单网卡学习先看它就能读懂许多场景；系统实际如何决定查哪张表，还涉及规则，放到进阶篇展开。[路由命令参考](https://man7.org/linux/man-pages/man8/ip-route.8.html)

## 7. 用一个完整路径把输出连起来

~~~text
Linux主机                  网关                  远端服务
10.10.10.10/24 -- ens160 -- 10.10.10.1 -- 网络 -- 203.0.113.80
~~~

203.0.113.80是文档示例地址，不要求你去访问它。按上面的路由表：访问同网段10.10.10.20时，/24更具体，从ens160直接交付；访问203.0.113.80时，使用默认路由，经10.10.10.1从ens160发出。

应用未指定另一个源地址时，普通场景下可能选择10.10.10.10。下一跳MAC属于10.10.10.1，不是远端203.0.113.80，这与你已有的路由交换知识一致。

可以让Linux解释一次路由查询：

~~~bash
ip -4 route get 203.0.113.80
~~~

示例输出：

~~~text
203.0.113.80 via 10.10.10.1 dev ens160 src 10.10.10.10
~~~

这里get表示查询给定条件下如何到达一个目标。它不实际发出测试包，输出也不证明远端服务可访问。

## 8. 下一跳是否已解析

在以太网IPv4场景，可以查看邻居表：

~~~bash
ip -4 neigh show dev ens160
~~~

示例：

~~~text
10.10.10.1 lladdr 00:11:22:33:44:55 REACHABLE
~~~

lladdr表示link-layer address，也就是这里的链路层MAC。该行说明邻居表里有网关地址到MAC的关系及状态。REACHABLE表示近期确认可达；STALE表示没有近期确认，不应仅凭这个词认定已经故障。INCOMPLETE或FAILED则需要进一步调查解析过程。

此时你能把三个观察连接起来：接口有地址→路由选择网关与出口→邻居信息说明如何给下一跳交付。远端服务和返回路径仍需后续验证。

## 9. 第一次观察的操作顺序

每次执行一条，并用自己的输出代替示例：

1. ip -br link show：记下实际接口名称。
2. ip -br address show：找到实验接口的IPv4地址。
3. ip -4 route show：找直连前缀与默认网关。
4. ip -4 route get 后接你实际环境的一个目的地址：解释出口与源。
5. ip -4 neigh show：观察网关邻居，条目可能因尚无相关流量而不存在。

这些是读取状态的操作，没有要求改变地址、默认路由或关闭网卡。如果目前没有Linux实验环境，先读输出与判断，环境准备见[实验说明](../../../Network-Career-Lab/00-Plan/Lab-Environment.md)。

## 10. 常见错误先按文字解释

| 看到什么 | 第一层解释 | 下一步 |
|---|---|---|
| ip: command not found或类似提示 | 当前Shell没有找到ip工具 | 确认在Linux中，检查工具安装与命令路径 |
| Device ... does not exist | 指定的接口名在当前环境不存在 | 回到接口列表，使用实际名称 |
| 路由列表没有default | 此表没有默认路由，不代表所有目的都不可达 | 看目标是否有直连或更具体路由 |
| route get提示不可达 | 此查询条件没有可用结果或命中相应拒绝结果 | 核对目的和路由；复杂策略后续学习 |
| 地址正确但业务不通 | 仅满足了部分条件 | 查路由、邻居，再查过滤、服务与回程 |

不要用一次command not found解释成网卡故障，也不要因为示例用了ens160就去给自己的系统随意改名。

## 11. 自测与下一步

1. ens160和ip分别是什么？答案：前者是示例接口名，后者是工具名。
2. main是什么？答案：Linux的一张普通路由表名称，不是网卡，表号254。
3. table main与default via ...有什么区别？答案：前者指定表，后者是一条默认路由。
4. dev与via分别指什么？答案：出口接口与下一跳。
5. route get成功是否证明已访问目标？答案：没有发包，只是查找结果。
6. lo为什么不需要接交换机？答案：它是本机回环接口。

先把实际主机的“接口名→IP→直连路由→网关→出口”讲顺，再读[策略路由与VRF进阶](02-Policy-Routing-and-VRF.md)。进阶篇保留多网卡、查表规则与VRF案例，不作为第一遍入门要求。

本次为文档讲解与示例核对，未在Linux平台执行这些命令。正式实验的注入、恢复与证据要求在配套实验手册完成。
