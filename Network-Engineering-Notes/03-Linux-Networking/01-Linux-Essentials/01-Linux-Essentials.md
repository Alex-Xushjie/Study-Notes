# Linux入门：先认识系统，再学习网络命令

[Linux学习目录](../Linux-Networking.md) · [下一篇：进程、服务与软件包](02-Processes-Services-and-Packages.md)

## 1. 你的起点：懂网络，但刚开始使用Linux

本部分假定你知道路由、网关、VLAN等网络概念，但不假定你使用过Linux。先把操作环境、系统组件和命令表达方式讲清楚，后面再把已有网络知识映射进去。

第一遍只需要做到：知道命令在哪里执行，能读懂命令由哪些部分组成，知道网卡名和路由表名表示什么。暂时不用配置复杂虚拟网络，也不需要先成为系统管理员。

## 2. Linux、Ubuntu和内核是什么关系

日常说“一台Linux服务器”，通常指运行某种Linux发行版的计算机。发行版是一套可安装使用的系统，例如Ubuntu、Debian和Rocky Linux。它把Linux内核、基础工具、软件管理与其他组件组合起来。

内核是操作系统的核心部分，负责管理CPU、内存、设备，并提供网络等能力。Ubuntu是发行版名称，Linux内核只是其中的一部分。两者都有版本，因此“Ubuntu版本”和“内核版本”不能当成同一个数。

网工可以先这样理解一台常见Linux服务器：

~~~text
你：查看状态、执行命令
        ↓
终端窗口中的Shell：接收并解释命令
        ↓
ip、ping、其他应用：完成具体工作
        ↓
Linux内核：网络处理、CPU/内存与设备管理
        ↓
驱动及硬件/虚拟硬件：网卡、磁盘等
~~~

这是一张职责关系图，不是每个报文的精确调用流程。网卡驱动负责让系统与相应设备协作，内核网络栈负责诸如IP和TCP等处理；ip命令是查看或配置网络的工具，不是负责转发每个包的常驻路由进程。

## 3. 先认识这几个常用组件

| 名称 | 含义 | 后面为什么会遇到 |
|---|---|---|
| Terminal，终端 | 输入文字命令、显示结果的窗口或会话 | 你在这里操作Linux |
| Shell | 接收、解释命令并组织执行的程序，Bash是常见一种 | 决定输入怎样被理解 |
| Program，程序 | 安装好的可执行工具或应用 | ip、ping等属于程序 |
| Process，进程 | 程序运行时的实例，有进程编号PID | 排查服务、CPU占用时需要 |
| Service，服务 | 为某种功能持续提供工作的程序及其管理方式 | SSH、DNS等可能以服务运行 |
| systemd | 很多发行版使用的启动与服务管理组件 | 后面用systemctl查服务、journalctl查日志 |
| Package，软件包 | 可安装、更新的软件单元 | ip工具通常由iproute2包提供 |
| Network manager，网络管理组件 | 按配置管理地址、路由等网络设置 | 解释为什么临时改动重启后消失或被改回 |

systemd和NetworkManager不是同一个组件。很多系统也不使用完全相同的软件组合，先认识职责，不必背全部产品名。

## 4. Windows用户应该在哪里输入命令

本笔记中的ip、uname、cat等命令在Linux环境中执行。Windows PowerShell有自己的命令和语法，在其中输入Linux示例不一定有效。

你可以通过Linux虚拟机的控制台，或已经建立好的SSH会话进入Linux。虚拟机是在当前计算机上运行的另一台虚拟计算机，它有自己的系统、网卡和地址；虚拟机的网络设置还可能包含NAT或桥接，这与Linux内部的地址配置是不同层。

SSH是一种远程登录方式：会话建立后，输入的Linux命令在远端机器执行。文件也会从远端读取，而不是自动读取Windows的E盘。先确认当前主机，再解释输出。

如果还没有Linux环境，先按[实验环境说明](../../../Network-Career-Lab/00-Plan/Lab-Environment.md)准备专用Linux VM；此篇不要求你现在就建立VRF或多网卡拓扑。

## 5. 一行命令应该怎样读

### 5.1 提示符不是命令的一部分

终端可能显示：

~~~text
alex@linux-lab:~$ ip -br address show
~~~

这里alex是用户名，linux-lab是主机名，~表示当前位于用户家目录，末尾$通常表示普通用户提示符。具体提示符可定制，因此不要仅凭外观当作权限证明。

真正输入的是：

~~~bash
ip -br address show
~~~

书上如果出现$或#作为提示符，不应一起复制。代码行开头的#也常用于注释，表示说明文字；判断时看作者是否在展示提示符。本笔记的可执行命令代码块尽量省略提示符。

### 5.2 命令、选项和参数

~~~text
ip        -br        address       show
工具名    显示选项   操作对象       动作
~~~

ip是工具名称；-br是brief的缩写，要求简短显示；address表示地址对象；show表示查看。空格用于分隔各部分，通常区分大小写。

再看另一条：

~~~bash
ip address show dev ens160
~~~

dev表示device，也就是“指定设备/接口”；ens160是要查询的接口名称。它相当于说：“使用ip工具，查看ens160这个接口的地址。”下一篇会详细解释为什么接口可能叫ens160。

### 5.3 命令结束后，屏幕上是什么

工具会显示结果，或者显示错误。出现提示符一般表示这个前台命令结束，你可以继续输入；没有提示符可能是程序仍在运行或等待输入。

man用于打开本机手册，例如man ip。手册常用分页器显示，按q退出。Ctrl+C通常向当前前台程序请求中断，不表示把它已经造成的配置变更自动撤销。[Ubuntu命令行入门](https://ubuntu.com/desktop/docs/en/latest/tutorial/the-linux-command-line-for-beginners/)

## 6. 用户、root与sudo

普通用户适合日常查看与操作；root是高权限管理用户。sudo用于按系统授权，以其他身份运行指定命令，常见用途是使用管理员权限。它不是所有Linux命令的固定前缀。

许多网络查看命令不需要sudo，修改系统网络和查看某些进程信息可能需要权限。sudo提示输入密码时，终端通常不显示输入字符，按提示完成即可，不要因为没星号就反复粘贴。

本阶段先学习查看。看到Permission denied，应先理解操作对象和所需权限；不能把权限错误、工具未安装和网络故障混为一谈。

## 7. 文件系统：配置、状态与日志在哪里

Linux路径以/开头，/称为根目录。它与root用户是两个不同概念。/home/alex是一个绝对路径；~代表当前用户家目录，不是固定等于/home/alex。

| 路径 | 第一遍需要知道什么 |
|---|---|
| /etc | 许多系统或服务配置所在位置；不保证所有软件都放这里 |
| /home | 常见普通用户家目录所在位置 |
| /var/log | 许多日志所在位置；有些日志通过journalctl读取 |
| /proc | 内核和进程信息的虚拟文件系统，内容通常由运行状态生成 |
| /sys | 向用户空间呈现设备和内核对象等信息的接口 |
| /usr/bin、/usr/sbin等 | 许多已安装工具所在位置；布局由系统决定 |

cat用于把文件内容显示到终端；ls列出目录内容；pwd显示当前目录；cd切换当前目录。例：cat /etc/os-release读取系统标识信息，不会修改文件。

/proc不像普通文本笔记那样只是磁盘上保存的一段固定内容，它提供运行中的系统信息。后续读取/proc/interrupts是在观察中断统计，不是打开一份手工维护的报表。[内核/proc说明](https://docs.kernel.org/filesystems/proc.html)

## 8. 配置文件、当前状态和管理组件

Linux里可能同时存在三样东西：配置文件、负责应用配置的管理组件、内核当前生效的状态。三者不应混淆。

例如，管理员通过工具临时加一条路由，内核立刻使用；重启或网络管理组件重新应用配置后，它可能消失。也可能文件已经改了，但尚未被正确应用。不要套用“执行所有CLI后统一write memory”的固定模型。

常见名称包括NetworkManager、systemd-networkd，以及用于描述并生成后端网络配置的Netplan。它们之间有不同职责和组合方式，后面在讨论持久化配置时再按实际系统展开；不要求你现在编辑任何网络配置文件。

软件包管理也随发行版不同。Ubuntu常见apt，其他发行版可能用dnf等。看到command not found，先确认拼写、工具是否安装以及当前环境，不直接判定网卡或路由有问题。

## 9. 第一次登录，只做这七项观察

每次一条，读完输出再继续。以下命令需要在Linux中执行，输出随机器不同。

| 输入 | 逐项含义 | 要记下什么 |
|---|---|---|
| hostname | 查看主机名 | 当前是哪台机器 |
| whoami | 查看当前用户名 | 使用什么账号 |
| pwd | print working directory，显示当前目录 | 当前文件路径起点 |
| cat /etc/os-release | cat读取系统标识文件 | 发行版名称与版本 |
| uname -r | uname查询系统信息，-r显示内核release | 内核版本，不是发行版版本 |
| ip -V | ip的版本查询 | 工具版本；大写V |
| ip -br link show | 简表查看网络接口 | 实际有哪些接口名称 |

如果ip不存在，记录错误并确认系统的软件包，不需要为了继续看笔记盲目安装一串工具。此处也不要求所有接口名称与示例一致。

## 10. 进入网络专题前的自测

请用自己的话回答：Ubuntu与Linux内核是什么关系？终端和Shell有什么区别？SSH登录后命令在哪台机器执行？ip是工具还是接口名？sudo有什么作用？配置文件与当前网络状态为什么可能不同？

参考要点：发行版包含内核与其他组件；终端负责交互呈现，Shell解释命令；SSH会话中的命令在远端执行；ip是工具；sudo按授权切换执行身份；当前状态可能是临时设置或尚未应用配置的结果。

能回答这些问题，先继续[进程、服务与软件包](02-Processes-Services-and-Packages.md)，再读[网卡、地址与普通路由](../02-Interfaces-Routing-and-VRF/01-Interfaces-and-Routing.md)。本篇不要求背诵系统目录，也不把后面的VRF、Namespace或性能术语作为入门前提。
