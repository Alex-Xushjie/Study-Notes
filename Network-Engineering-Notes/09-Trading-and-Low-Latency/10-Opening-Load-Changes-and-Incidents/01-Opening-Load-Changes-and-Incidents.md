# 开盘负载、变更与事故处置

[返回本部分学习目录](../Trading-and-Low-Latency.md)

## 1. 按真实业务日历准备

开盘/竞价/重连/发布与日切由提供方和业务规则决定，跨市场/夏令时不能用一个固定本地时间概括。变更与监控关联实际日期、时区和session，提前核对服务公告与维护窗口。

开盘可能同时出现消息突发、客户端订阅/Recovery、身份/会话和应用缓存峰值。基线不仅看字节数，还看pps、包长、频道、突发、队列、CPU、时钟与业务状态。

## 2. 值班视图

| 视图 | 关键项 |
|---|---|
| A/B输入 | 单路序号gap、重复/乱序与最后有效点 |
| 合流/恢复 | 缺口、缓存、补包和数据有效性 |
| 路径 | 端口/队列/错误、PIM/RPF与路由变化 |
| 主机 | NIC/内核/Socket、CPU/NUMA、磁盘与日志 |
| 时间 | GM身份、Offset/状态、误差告警 |
| 应用 | 处理积压、关键事务与受影响范围 |

## 3. 事故顺序

先确定业务影响和受影响频道/会话，按预案由业务系统决定暂停/降级或切路；网络采集事实并保留短窗口证据。业务恢复和根因确认可以分阶段，但不能恢复后不复盘。

禁止事故中全局清组播/路由、随意切双路或更改时钟来试错。紧急动作仍需明确范围、授权、原值、观察点与恢复路径。

## 4. 变更

A/B分批、固定生成物与基线、单故障域灰度、保留带外和原版本。网络、内核/NIC、应用与时间配置有依赖，跨团队统一验证，不在同一窗口同时改多个变量后无法归因。

## 5. RCA练习

场景为开盘gap增加但平均链路15%、PIM正常。分别给出口Microburst、NIC队列、Socket与记录器过载假设和反证。用相同序号与时窗关联，不能因B Feed正常就定位A故障。
