# 延迟预算、测量契约与尾延迟

[返回本部分学习目录](../Trading-and-Low-Latency.md)

## 1. 把总时延拆开

传播、序列化、设备处理、排队、NIC/内核与应用分别占用时间。光纤传播可用约5微秒/公里作教学近似；真实路线不是地图直线，设备与介质也会增加差异。

1500字节按纯比特序列化：10Gb/s为1.2微秒，100Gb/s为0.12微秒，尚未加以太网开销。多跳是否重复计入、Cut-through是否重叠要遵循模型，不能把所有数据表数字机械相加。

## 2. 测量契约

| 项目 | 需声明 |
|---|---|
| 起止点 | 线路入口→出口、NIC→应用或业务事件？ |
| 时间源 | 软件/硬件时间戳、时钟域与同步误差 |
| 负载 | 包长分布、pps、突发、并发与背景流 |
| 样本 | 数量、窗口、缺失与过滤规则 |
| 统计 | P50/P99/P99.9、最大值、丢包和方法 |

## 3. 平均数的局限

平均改善可能伴随尾延迟或丢包变差。超时样本若被剔除，会让坏系统看起来更快。按相同业务和样本规则比较，报告吞吐、尾延迟、完整性和CPU/资源。

单向时延需要可比较的时钟和已知误差；RTT除2仅在适当对称假设下近似，不能证明真实单向值。没有足够时钟能力时测同点间隔或RTT并明确边界。

## 4. 练习

给2km光纤、三台设备各0.5微秒、一次100G上1500字节序列化、主机5微秒的简化模型，总约16.62微秒。注明只计一次序列化和给定处理预算，真实网络不可直接照抄。

[延迟度量RFC7679](https://www.rfc-editor.org/rfc/rfc7679.html)、[Linux时间戳](https://docs.kernel.org/networking/timestamping.html)。
