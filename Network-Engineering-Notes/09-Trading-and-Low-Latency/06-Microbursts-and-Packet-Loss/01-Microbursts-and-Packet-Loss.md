# 微突发、Buffer与丢包定位

[返回本部分学习目录](../Trading-and-Low-Latency.md)

## 1. 平均利用率看不到队列峰值

多个入口同时向同一出口发送，瞬时输入超过输出就积压。若入口合计25Gb/s、出口10Gb/s持续100微秒，理想积压为(25−10)×10^9×100×10^-6/8=187500字节。实际包粒度、共享池与阈值还会影响。

Buffer吸收有限突发，但1MB排队在10Gb/s上仅按十进制数据序列化就约0.8毫秒，远高于一些空载设备处理延迟。大Buffer减少丢失也可能增加尾延迟，不能只追求无drop。

## 2. 丢包分段

| 位置 | 证据 |
|---|---|
| 交换设备出口 | 队列丢弃、占用峰值、短窗速率 |
| 链路 | CRC/物理错误与实际接收 |
| NIC | Ring/驱动统计、队列与中断 |
| 内核/Socket | softnet、UDP/Socket drop与积压 |
| 应用 | 输入/处理队列、解析失败与业务序号 |
| 记录器 | 捕获丢失、SPAN/存储过载 |

同一时间可能多点丢失。累计计数需做差值并对齐频道与窗口，单个全局drop不足以直接归因目标gap。

## 3. 修复选择

入口整形、应用发送节奏、分散复制、扩出口、队列规划或接收端资源调整针对不同根因。扩大接收Buffer不会修复交换机先丢包；换交换机也不修复应用消费不足。

## 4. 练习

设计固定输入总量但不同突发长度的测试，比较延迟分位数、丢包、队列和CPU。避免对生产或第三方满速注入，只有隔离环境验证容量。没有短窗遥测时如实说明不能排除Microburst。
